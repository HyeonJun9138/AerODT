# 웹 도메인 경계

현재 구현 범위는 브라우저 도메인 선택, 화면과 활성화 경로 분리다. 서버 런타임이나 우주 동역학을 새로 구현한 것이 아니다.

## 공용 셸

- `domain_catalog.js`: 도메인별 표시 개체와 자료 설정 범위. 읽은 스냅샷을 필터링할 뿐 원본이나 런타임 상태를 수정하지 않는다.
- `domain_chooser.js`: 매 페이지 로딩 후 명시적 선택. 선택을 저장해 다음 실행에서 자동 진입하지 않는다.
- `domain_shell.css`: 선택 화면과 도메인 표시.
- 상위 웹 폴더의 `app.js`: 기존 구성 요소의 조립 지점. 현재 UAM 조립 코드 일부는 여기에 남아 있다.
- 지도, 창 배치, 공통 렌더링 품질, 지형과 영상 설정은 공유한다. 공통 설정은 브라우저 단위이며, 도메인 선택으로 서버 수집 설정을 쓰지 않는다.

## UAM

| 폴더 | 책임 |
|---|---|
| `uam/cockpit` | 조종석, PFD와 NAV, 수동 조종 표시 및 연결 |
| `uam/operations` | PSU, 버티포트, 조종사와 이해관계자, 공유 운항 절차 |
| `uam/planning` | 항로, 단일 비행과 다중 비행 구성, 수요와 임무계획 |
| `uam/live_twinning` | 물리 UAM과 트윈 상태, 관측 시험 화면 |
| `uam/prediction` | 예측 화면과 충돌 위험 표시 |
| `uam/analysis` | 운항 분석 화면과 조회 요청 |
| `uam/audio` | UAM 기체/현장 사운드의 브라우저 연결 |

기존 구현 55개를 이동했다. 기존 경로는 구 버전 진입점과 다른 개발 작업의 import를 깨뜨리지 않도록 re-export만 남겼다. 새 코드는 실제 도메인 경로를 import한다. 동일 구현을 두 군데 유지하지 않는다.

UAM 선택 후에만 운항 환경 갱신, 변경 감시, 재생 예측 갱신, 사운드, 운항 자료 초기 조회를 활성화한다. 항공기와 UAM에 더해 새/드론 장애물과 인식 결과도 UAM 표시 범위에 포함한다.

## Satellite

`satellite/workspace.js`는 지구 시점과 기존 위성 위치 스트림/시각 모델 목록을 표시한다. 임무계획, 이해관계자 운영, Prediction 및 운항 분석은 준비 중이라고 표시하며 UAM 화면으로 연결하지 않는다. Satellite에서는 기체 사운드를 생성하지 않는다. 건물, 공역, 버티포트 이름표와 그 상세 성능 설정은 제외한다.

## 도메인 전환

상단의 도메인 변경 버튼은 확인 후 페이지를 다시 로딩한다. 브라우저 조종 연결과 열린 창은 종료될 수 있지만, 서버의 공유 시뮬레이션을 reset/stop하지 않는다. 현재는 동작 중인 수동 비행의 무중단 도메인 전환을 지원하지 않는다.

## 다음 단계의 진입 조건

서버 상태 소유권과 API는 이번에 변경하지 않았다. 향후 위성 임무를 추가할 때는 먼저 아래 문서의 계층별 책임과 wire schema를 결정하고, 기존 UAM/위성 궤적 회귀시험을 확보한 뒤 서버의 혼합 코드를 작은 단위로 이동한다. 빈 미래 폴더나 임의의 위성 계산 엔진은 만들지 않는다.
