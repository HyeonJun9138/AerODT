# UAM 정기 운항계획의 용량 및 회복여유 기준

## 목적

다중 비행계획 생성기는 실제 운항 직전의 PSU 판단을 대신하지 않는다. 계획 생성 단계에서는 표준 운항시간, 버티포트 시설 자원, 기체 순환과 일정 회복여유를 적용한다. 공중 항로는 계획 단계에서 점유 자원으로 예약하지 않으며 충돌이 없는 것으로 가정한다. 실제 항로 분리와 지연은 후속 연구와 실행 중 PSU 판단의 범위다.

## 2026-09-21 기준시간 실험

현재 저장된 버티포트 19곳, 항로 노드 138개, 링크 270개와 AeroDT 4인승 쿼드 틸트로터 운항 프로필을 사용했다. 버티포트 내부에서는 연결된 모든 GATE/FATO 조합 244개를 측정했다. 공중 구간은 방향이 있는 모든 FATO 간 OD를 계산했으며 840개가 연결되고 60개는 연결되지 않았다.

실험은 `project_support/tools/calibrate_uam_schedule.py`로 재현한다.

## 계획 파라미터

현재 기본값은 `digital_twin/model_library/schedule_planning.py`에 있다.

- 출발 지상이동 하한: 177.5초
- 수직 이륙 하한: 13.7초
- 상승 및 정천이 하한: 46.1초
- 강하 및 역천이 하한: 45.1초
- 수직 착륙 하한: 22.8초
- 도착 지상이동 하한: 160.7초
- 동일 FATO 계획 간격: 60초
- 회항 회복여유: 120초

FATO 간격 60초는 이륙과 착륙 동작의 P95 중 큰 값인 45.9초를 30초 단위로 올림한 값이다. 회항 회복여유 120초는 충전시간 P80과 평균의 차이인 117.1초를 올림한 값이다. 이 값들은 인증 기준이나 실측 안전기준이 아니라 현재 모델을 위한 연구용 계획 파라미터다.

## 생성 절차

1. OD별 운항시간 내 수요와 연결되지 않은 수요의 부분 확산을 계산한다.
2. 각 OD에 대해 연결 가능한 FATO 조합별 항로와 시간을 만든다.
3. 터미널 단계의 계획 하한을 적용하고 순항시간은 설계 항로 값을 유지한다.
4. 출발·도착 FATO 예약 시각을 비교해 가장 빠른 FATO 조합을 선택한다. 항로 구간은 예약하지 않는다.
5. 간격을 만족하지 못하면 출발시각을 뒤로 이동하며 그 시간을 계획 자원 대기로 기록한다.
6. 도착 후에는 좌석 등급별 최소 회항시간과 실제 충전시간 중 큰 값을 사용하고 120초의 회복여유를 더한다.
7. 같은 기체는 이전 편의 회항 완료 전에는 다음 편에 투입하지 않는다.

## 계획과 실제 운항의 경계

계획 생성기는 정상 혼잡을 반영한 시간표를 만든다. PSU는 실제 점유, 지연, 기상 및 돌발 상황을 확인하고 필요하면 추가 지연이나 재배정을 수행한다. 계획 슬롯이 있다고 해서 실제 이착륙 허가가 발생하는 것은 아니다.

현재 계획 용량 모델의 자원은 GATE, FATO, 기체와 회항시간이다. 공중 항로는 충돌이 없는 것으로 가정하며 방향, 고도층과 구간 점유시간을 계산하지 않는다.

현재 충전기 수는 저장된 19개 버티포트에서 GATE 수와 동일하므로 GATE 점유가 충전기 점유도 함께 제한한다. 향후 충전기가 GATE보다 적은 시설을 도입할 때는 충전기별 별도 예약 달력이 필요하다.


## 다중 비행 GUI에서 조절하기

UAM / Simulation > 비행 계획 > 다중 비행의 6번 **스케줄링 기준**에서 동일 FATO 사용 간격과 다음 운항 전 회복여유를 초 단위로 수정한다. 서버 기본값을 읽어 표시하며, 고급 항목을 펼치면 출발 지상이동부터 도착 지상이동까지 여섯 단계의 계획시간 하한을 조절할 수 있다. 모델 평균과 서버 기준값은 비교용으로 함께 표시한다.

단계별 값은 고정 운항시간이 아니라 계산값이 더 짧을 때 적용하는 하한이다. 계획 기준만 기본값으로 되돌릴 수 있으며 다른 수요·버티포트 선택은 유지된다. 빈 값이나 0~3600초 밖의 값은 생성 전에 막는다. 생성 요약에는 선택한 FATO 간격과 회복여유를 표시하고 실제 생성 요청에도 같은 값을 전달한다. 기존 운항 상태나 PSU 허가 기준을 변경하지 않는다.
