# 사용자 DEM 사전 보정

## 시가지 강한 보정 프로필

`--profile urban_strong`은 기존 `conservative`와 별도로 생성하는 시각화용 프로필이다. 기존 파일을 덮어쓰지 않는다. 건물의 `render_height`나 `render_min_height`는 지면의 해발고도가 아니므로 지면 기준점으로 사용하지 않는다.

- 건물 윤곽과 주거/상업/공업/학교 등의 토지 이용 면을 보정 영역으로 추가한다. 일반 도로(minor/service/residential/unclassified)도 포함한다.
- 건물 면을 제외한 주변 지표 표본으로 배경 높이를 추정한 뒤, 9표본 opening과 5표본 closing, sigma 4표본 평활화를 조합해 작은 돌출과 구멍을 줄인다. 실제 건물 높이를 DEM에서 빼는 방식은 아니다.
- 시가지 수정량 상한은 80 m, 도로 목표면은 60 m, 일반 완경사 지표는 12 m, 공항은 60 m, 수면은 20 m이다. 이것은 정확도나 오차 보장이 아니라 시각적 변형의 상한이다. 도로가 시가지와 겹치면 시가지 보정도 적용되므로 총 변화량은 최대 80 m일 수 있다.
- 도로 중심선 주위 최대 45 m와 시가지 외곽 90 m에는 가중치를 줄이며 연결한다. 이 거리는 실제 도로 폭이나 대지 경계의 측량값이 아닌 시각적 보정 영향 범위다.
- 넓은 범위의 경사를 남기고, 숲/암반/습지와 지상 교량 표식, 수변 육지 표본은 강한 보정에서 제외한다. 제외 구역과 실제 경사면에는 요철이 남을 수 있다. 도시 안의 작은 실제 둔덕이나 절개면도 함께 완화될 위험이 있다.
- 자연지형 바깥 60 m, 교량 및 수변 보호 구역 바깥 120 m에서는 보정량을 점차 줄여 원래 높이에 연결한다. 높은 원본 표본을 유지한 보호 구역과 낮춘 시가지 사이에 급격한 단차가 생기지 않도록 한다. 지형/벡터의 위치 오차나 보호 구역 내부의 원본 오류까지 해결하는 것은 아니다.
- 변경 종류 마스크의 5는 시가지이며 3은 도로 영향 영역이다. 원본과 기존 약한 보정본을 유지하고 QA 비교 후 연결해야 한다.

이는 건물과 도로의 분포를 제약 조건으로 사용한 추정 지면이다. 독립적인 DTM이나 측량 지표면을 확보한 것은 아니며, 충돌/착륙용 물리 표면을 변경하지 않는다. 새 패키지를 연결하고 서버를 재시작한 뒤 기존 브라우저도 새로고침해야 새 manifest version과 캐시가 일치한다.

반복 보정은 `--reuse-masks <기존_출력>`으로 벡터 래스터화 결과만 재사용할 수 있다. `mask_cache.json`의 입력 DEM 해시, MBTiles 해시, 격자/프로필과 모든 마스크 파일 해시를 확인한 뒤 새 출력에 복사한다. 어느 하나라도 다르면 거부하며 기존 출력에 덮어쓰지 않는다. `review_conditioned_dem <새_출력> --baseline <기존_보정본>`은 동일 원본으로 만든 자료인지 확인하고 같은 평가 마스크에서 기존 보정 대비 요철 변화도 기록한다.

`project_support/tools/condition_dem.py`는 SRTM GeoTIFF와 OpenMapTiles 계열 벡터 MBTiles를 결합하여 **시각화용 지형**을 생성한다. 실행 중인 시뮬레이터 설정과 충돌 판정용 지표면을 변경하지 않는다. 원본을 덮어쓰지 않으며 이미 존재하는 출력 폴더도 거부한다.

### 고층 밀집지 및 강변 도로 보완

- 건물 윤곽에서 2표본까지 주변을 확장해 높은 건물 주변 표본이 배경 높이 추정에 들어가는 것을 줄인다. 건물 밀도가 높은 구역에는 25표본 opening을 혼합하되 기존 국소 목표면 대비 추가 변화는 12 m로 제한한다. 전체 최대 변경 상한은 기존 80 m이다.
- 지하철이나 터널, 음수 layer는 지상 보호 마스크로 사용하지 않고 지상 도로로도 간주하지 않는다. 지상 교량과 양수 layer는 계속 보호한다. 이 분류 변경 때문에 마스크 캐시는 schema_version 2부터 허용하며 이전 마스크를 무조건 재사용하지 않는다.
- 수변 7표본 보호대에서 실제 지상 도로 중심선 45 m 이내의 육지 구간만 보정 가능하게 한다. 물에 바로 붙은 1표본 제방, 자연지형, 교량은 계속 보호한다. 고가도로 자체를 평탄화하거나 실제 제방 높이를 재측량한 것이 아니다.
- 96표본 halo의 블록/전체 결과 일치, 지하 교통 제외, 강변 도로와 바로 옆 제방 분리, 고층 밀집 표본의 회귀시험을 포함한다.

## 기본 conservative 프로필의 입력과 처리

- 현재 입력 계약은 WGS84 경위도, Point 표본, 동일한 간격, EGM96 수직 기준을 가진 단일 밴드 GeoTIFF이다. `DTED_VerticalDatum=E96` 태그를 확인한다.
- 벡터 타일은 읽기 전용 SQLite 연결로 해석한다. TMS 행 방향과 MVT 화면 좌표를 경위도로 변환하고, 원본 DEM 표본 위치에 공항과 수면 폴리곤, 도로 중심선을 래스터화한다.
- 지형은 하나의 표본 격자로 조합한 뒤 처리한다. 필터 블록에는 주변 여유 영역을 넣고 공항 면은 원본 타일 경계를 넘어 한 번에 적합한다. 동일 위치에 중복된 표본의 높이가 1 m를 넘게 다르면 입력 검토를 위해 중단한다.
- 일반 지표면의 작은 요철은 1~4도 경사에서 강도를 줄여 처리한다. 변경량은 최대 2 m이다. 고도가 낮다는 이유만으로 산지까지 평탄화하지 않는다.
- 수면은 수면 내부 표본만 사용해 국소적으로 완화하고 변경량을 최대 8 m로 제한한다. 강 전체를 같은 높이로 만들거나 흐름 방향을 강제하는 수리학적 보정은 아니다. 강둑과 섬의 육지 표본은 보존한다.
- 공항 면은 이상치 영향을 줄인 경사 평면을 적합한다. 적합 경사가 2도를 넘으면 건너뛰며, 수정량은 최대 12 m로 제한한다. 따라서 원본의 깊은 구멍과 큰 돌출부가 완전히 제거되지는 않을 수 있다. 폴리곤 경계에서는 변경량을 부드럽게 줄인다.
- 도로는 교량, 터널, 고가·지하 표식을 제외한 주요 도로 중심선에 한정한다. 실제 도로 폭과 고가 상판을 추정하여 평탄화하지 않는다. 폭이 없는 활주로 선도 공항 면으로 확대하지 않는다.
- 원본 NoData와 없는 지역은 그대로 남긴다. 30 m급 표본을 1 m 측량 지형으로 바꾸는 처리가 아니다. 또한 30 m는 표본 간격이지, 각 30 m 구역이 수평이라는 뜻이 아니다.

## 출력

- `merged_conditioned_30m.tif`: 입력 전체 범위를 합친 단일 GeoTIFF. 없는 지역은 NoData이다.
- `geotiff/*_conditioned.tif`: EGM96 기준 보정 높이.
- `geotiff/*_change_m.tif`: 원본 대비 수정량.
- `geotiff/*_mask.tif`: 변경 종류. 0=유지, 1=완만한 육지, 2=수면, 3=도로 중심선, 4=공항, 255=NoData.
- `package/manifest.json`과 float32 데이터: 기존 LocalDem reader용 패키지. 런타임은 저장된 EGM96 높이에 지오이드 높이를 한 번만 더해 타원체 높이를 얻는다.
- `report.json`: 입력 해시, 범위, 파라미터, 공항 적합 결과와 수정량 통계.
- `build_arrays`: 중간 합성 격자와 마스크. 생성물이며 소스 저장소에 포함하지 않는다.
- 검토 도구를 실행하면 `qa/validation.json`과 김포공항, 한강, 북한산의 비교 그림을 만든다. 거칠기는 Gaussian sigma 1.2 표본을 뺀 고주파 성분의 RMS이며 지형의 절대 정확도 지표가 아니다.

## 재현

격리된 Python 환경에 `project_support/tools/terrain_build_requirements.txt`의 의존성을 설치한다. 운영 서버 환경에 GIS 패키지를 설치할 필요는 없다.

```powershell
python -m project_support.tools.condition_dem --source <입력_DEM_폴더> --mbtiles <벡터.mbtiles> --geoid <us_nga_egm96_15.tif> --output <새_출력_폴더>
python -m project_support.tools.review_conditioned_dem <출력_폴더>
python -m pytest project_support/tests/web_live/test_condition_dem.py project_support/tests/web_live/test_local_terrain.py -q
```

사용한 지오이드 파일은 [PROJ 배포 NGA EGM96](https://cdn.proj.org/us_nga_egm96_15.tif)이다. 해당 파일의 CRS는 WGS84 3D(EPSG:4979)이므로 4326만 허용하는 판정은 부적합하다. 대상 높이 EPSG:5773과 밴드 설명 `geoid_undulation`도 확인한다. SRTM 높이 기준은 [USGS SRTM 자료 설명](https://www.usgs.gov/centers/eros/science/usgs-eros-archive-digital-elevation-shuttle-radar-topography-mission-srtm)을 참고한다.

## 적용 전 확인

2026-09-21부터 설정 → 지도 표시 → 지형 자료의 **보정 DEM 사용**으로 선택할 수 있다. 기본 선택은 바꾸지 않는다. `conditioned_dem_directory` 배포 설정으로 패키지를 지정하며 현재 연결된 패키지는 `conditioned_urban_riverside_20260921/package`이다. 이전 강화본 `conditioned_urban_max_20260921/package`도 유지한다. 이전 `conditioned_srtm_20260921/package`도 복원용으로 유지한다. 브라우저 선택은 이 PC의 해당 origin에 자동 저장된다. 기존 사용자 로컬 DEM과 보정 DEM은 독립된 공급자이며 `Cesium World Terrain`으로 돌아갈 수 있다. 보정 지형으로 바꾸어도 native/수동 비행 서버의 지면 판정은 교체하지 않는다.

데이터 생성과 reader/타일 호환성 검증에 이어 설정 전환과 실제 Cesium 타일 로딩을 확인했다. 운항에 사용하기 전에는 김포공항과 한강의 실제 화면, 경계 혼합, 버티포트 높이 정합, 지상 이동을 확인해야 한다. 특히 시각화용 지형과 물리 지상 판정이 다른 상태로 운항 검증을 완료했다고 판단하면 안 된다.

MBTiles의 water `class=lake`가 강에도 쓰여 이름만으로 호수 전체를 수평화하지 않는다. 원본 벡터의 출처와 이용 조건, 공항 경계의 정확성도 별도로 확인해야 한다. 보정 지형은 측량, 안전 운항, 정밀 착륙 판정 자료가 아니다.
