# ADR 0032: 도착 지상이동 방향을 공중에서 정렬

- 날짜: 2026-09-10
- 상태: 채택

## 문제

현재 착륙 기수는 접근 방향을 유지한다. 도착 FATO에서 게이트로 나가는 지상이동
접선이 다르면 접지 후 제자리 정렬이 필요하다. 사용자는 이를 착륙 전 상공에서
완료하고 같은 방향으로 수직 착륙하기를 요청했다.

## 결정

native runner 입력에 선택적 `landing_yaw <degrees>`를 추가하고 RoutePilotProfile의
`landing_yaw_deg`로 전달한다. 유한한 각도만 받으며 생략 시 이전 유도를 유지한다.
기존 waypoint/state 행 형식은 변경하지 않는다. `smooth_flight 1`에서 적용한다.

native adapter는 도착 `gate_in`의 ground_motion 첫 접선에서 목표 기수를 읽는다.
이 정보가 없는 과거 계획은 첫 길이가 있는 taxi 선분을 사용하며, taxi 자체가 없으면
새 명령을 보내지 않는다. 게이트까지 직선 방위로 대체하지 않는다.

RoutePilot은 마지막 착륙 지점의 상공에서 중심 오차 0.6 m 미만, 수평 속도
0.4 m/s 미만 및 fixed-wing blend 0.01 미만일 때 목표 yaw를 바꾼다. 기존
최단각 및 초당 10도 명령 제한을 유지하고 SimpleFlight가 실제 자세를 제어한다.
하강 전에는 아래 관측이 1초 지속되어야 한다.

- 중심 오차 0.3 m 미만, 수평/수직 속도 0.2 m/s 미만, blend 0.01 미만
- 실제 yaw 오차 1.5도 미만, 명령 yaw 오차 0.5도 미만
- 실제 body yaw rate 초당 1도 미만

그동안 기존 도착 hover 높이를 유지한다. 정렬 후 동일 yaw를 유지하며 기존
하강 속도 및 실제 접지 확인을 사용한다. Runtime 상태, 제어기, 동역학, actuator와
이산 적분 순서는 변경하지 않는다. 위치나 기수를 사후 처리로 덮어쓰지 않는다.
기존 지상 정렬은 과거/방향 없는 입력 및 미세 잔차를 위한 방어 경로로 유지한다.

## 범위와 검증

이 변경은 native 경로 조종사에 한정하며 순수 kinematic fallback의 움직임은 바꾸지
않는다. 새 입력을 쓰려면 runner 재빌드와 서버 재시작 후 새 실행을 생성해야 한다.
저장된 과거 비행은 그대로 재생한다. 좌/우 90도, 180도, 북쪽 각도 경계의 실제
native 비행과 typed-goal 시험으로 공중 정렬 및 하강 차단을 검증한다.
실제 운항 승인, 장애물 여유, 바람 교란 및 Unreal 실행 승인은 별도 검증 대상이다.
