# ADR 0086: 공급자 항공기 GRU 보정 입력

## 결정 (2026-09-14)

사용자가 OpenSky의 낮은 관측 빈도를 보정하여 일반 항공기 GRU를 실행하도록 승인했다.
기존 가중치와 엄격한 16점/0.2초 입력 검증은 변경하지 않는다.

- `data/ingestion/aircraft_prediction_history.py`가 기체별 최대 32개 과거 원본 보고를 보유한다.
  application에서 생성하고 LiveSynchronizer의 선택적 `prediction_history` 인자로 주입한다.
  현재 World 상태와 생성한 입력은 보관하지 않는다.
- 관측 사이 선형 보간, 마지막 관측 이후 보고된 속도 벡터로 등속 외삽한다.
  첫 관측 이전으로 역외삽하지 않고 관측 경과 45초 또는 기존 상태 유효 한계에서 중단한다.
  긴 수신 공백, 위치 불연속, 시계 역행, 대상 삭제 시 과거 입력을 분리/제거한다.
- 생성한 ECEF 점을 기체 부근 ENU로 변환한 뒤 GRU를 실행한다. 출력은 기존
  trajectory schema_version=1 / kind=aircraft / ecef_m의 76개 점으로 반환한다.
  최대 예측 시간은 학습 계약의 15초다. 시뮬레이션 상태나 원본 보고를 변경하지 않는다.
- 기존 summary.basis에 `provider_corrected` 값을 사용해 주의 문구를 표시한다.
  이를 실제 5 Hz 관측 또는 검증된 정확도로 표현하지 않는다. 선회율을 보고하지 않는
  GRU에 대해 화면이 '직진'을 확정 표시하지 않도록 한다.
- 모델은 선택 대상의 경로 요청에서만 지연 로드하여 재사용한다. 전 기체 매 tick 추론은 하지 않는다.

## 검증과 한계

Python 관련 64 PASS, Node 화면 데이터/trajectory 24 PASS, Python/JS 구문 검사 PASS.
TestClient에서 GRU 선택 후 실제 checkpoint의 경로 76점 HTTP 200 확인.
로컬 추론 12회 중앙 1.28ms/최대 1.85ms (모든 환경의 성능 보장 아님).
운영 서버 재시작 및 실제 브라우저 장면, Unreal 신규 검증은 수행하지 않았다.
보정 입력의 예측 정확도는 미검증이다. 관측 간 선회 정보는 복원할 수 없다.
독립 리뷰를 요청했으나 모델 용량 오류로 실행되지 않아 자체 검토와 회귀시험을 수행했다.
