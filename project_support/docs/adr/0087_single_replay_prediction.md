# ADR 0087 단일 비행의 읽기 전용 예측 조회

상태: 적용, 2026-09-14

## 결정

저장된 단일 비행의 표시 시계는 기존 PlanPanel이 소유한다. 표시 어댑터는 기록을 기체 상세창과 Prediction 모니터에 전달할 뿐 World에 현재 상태를 추가하거나 제어 명령을 보내지 않는다. 라이브 스냅샷과 재생 스냅샷은 서로 다른 표시 문맥으로 유지한다.

GET `/api/simulation/runs/{run_id}/prediction?seconds=<cursor>&epoch=<epoch>`는 저장 좌표 기준의 예측을 조회한다.
POST 같은 경로는 `{seconds, epoch, heights}`를 받는다. heights는 원래 계획의 각 경로점 순서에 대응하는 표시용 절대 고도 배열이다. 좌표, 시각, 기체 상태 또는 임무를 변경하는 입력은 받지 않는다. 브라우저에서 이미 적용한 지형과 데크 고도를 같은 기준으로 사용하기 위한 것이다. 배열 길이와 수치 범위를 검증한다.

응답은 `{snapshot, prediction, run_id, cursor_seconds}`다. snapshot은 기록에서 읽은 상태의 표시 계약이며 라이브 World 스냅샷이 아니다. prediction은 기존 학습 비교 계약 또는 기존 단일 궤적 계약을 그대로 사용한다. 알 수 없는 실행은 404, 잘못된 입력은 422, 미연결 서버는 503이다. 모든 응답은 no-store다.

## 입력과 일관성

커서 시각까지의 40초 기록만 읽고, 단기는 최근 9.6초, 중기와 장기는 최근 28.8초를 25개 입력 표본으로 만든다. 모델의 미래 출력 간격과 과거 입력 간격을 혼용하지 않는다. 미래 기록은 예측 입력에 포함하지 않는다. 알려진 계획의 남은 경로는 사용할 수 있다.

회귀 및 기체나 설정 변경은 브라우저 요청 세대를 무효화한다. 서버 예측 캐시 문맥에는 실행 ID, 재생 epoch, 표시 고도 해시가 포함된다. 추론은 시뮬레이션 루프나 World를 수정하지 않는다. 기록 재생과 연구용 예측임을 화면에 표시한다.

## 검증 및 한계

관련 브라우저 89개 및 Python 27개 통과. 실제 저장 비행과 운영 서버 API에서 세 모델 모두 준비 상태와 25개 미래 지점 반환을 확인했다. AirTaxi 단일 비행 브라우저 검증을 수행했다. 예측 정확도 또는 비행 안전성 입증은 아니다.
