# ADR 0112: 터미널 지정 항로 보존과 비행 궤적 표시 기준 일치

## 상태

채택

## 배경

도착 대기 위치를 비행 전 경로에 넣는 과정에서 기존 순항 종점을 낮은 FATO 주변
대기점으로 교체했다. 그 결과 기체가 지정된 접근 진입점에 도달하기 전에 도심 위를
길게 대각선으로 강하할 수 있었고, 화면의 단계는 여전히 순항으로 표시됐다. 출발
경로는 원래 지정된 상승 구간을 사용했지만 도착 대기 경로만 이 규칙을 깨고 있었다.

또한 Runtime이 기록하는 비행 궤적은 물리 고도를 그대로 저장하지만, 3D 기체는
버티포트 데크와 렌더링 지형의 높이 차이를 화면에서만 보정한다. 궤적에 같은 화면
보정을 적용하지 않아 일부 데크 주변에서 녹색 궤적이 기체 아래에 분리되어 보였다.

## 결정

PSU가 FATO 주변 대기점을 배정해도 게시된 순항 종점과 접근 진입점을 변경하지 않는다.
자동 조종사는 지정된 접근 진입점까지 원래 항로를 비행한 뒤에만 FATO 주변 대기점으로
이동한다. 대기점 이동은 강하 단계에 속하며, 대기 해제 후 최종 접근 권한 경로는
대기점을 제외하고 원래 착륙 시작점에서 시작한다. 출발의 수직 이륙과 상승 경로도
기존에 작성된 순서를 그대로 유지한다.

FATO 주변 대기 이동은 일반 항로를 대체하는 새 순항 경로가 아니다. 기존 정책대로
지형 높이, 이륙 경로, 다른 기체와 이동 경로를 확인하며, 확인할 수 없는 임의의 직선
단축은 허용하지 않는다. 원본 비행계획과 Runtime의 현재 위치는 이 과정에서 수정하지
않는다.

궤적 API에는 출발지와 도착지의 `surface_references`를 선택 필드로 추가한다. 각 항목은
버티포트 식별자와 시뮬레이션 데크 고도를 제공한다. 시각화는 실시간 기체에 쓰는 것과
같은 데크/지형 표시 오프셋을 과거 궤적 점에도 적용하고, 데크 영향 범위를 벗어나면
기존 보간 규칙에 따라 오프셋을 0으로 줄인다. 저장된 고도와 물리 계산에는 이 값을
반영하지 않는다.

## 책임

- 비행계획과 항로망은 상승, 순항, 접근 및 착륙의 지정 점 순서를 소유한다.
- PSU는 FATO 주변 대기 위치와 해제 순서를 결정하지만 지정 접근 진입점을 삭제하지 않는다.
- Pilot은 허가된 지정 항로와 대기 이동을 실행한다.
- Runtime은 물리 위치와 기록 궤적의 유일한 소유자다.
- Visualization은 데크/지형 차이를 화면에만 보정한다.

## 결과

도착편은 더 이상 멀리 떨어진 순항점에서 낮은 대기점으로 바로 강하하지 않는다.
대기가 필요해도 지정 접근 진입점까지 비행한 뒤 터미널 주변에서 대기 절차를 수행한다.
녹색 비행 궤적과 기체는 데크 주변에서 같은 화면 높이 기준을 사용한다.

이 결정이 3D 건물 형상을 별도의 충돌 지도로 바꾸는 것은 아니다. 안전 근거는 작성된
항로와 현재 지형·교통 검사이며, 건물 모델과 항로 데이터가 불일치하면 항로 제작 또는
장애물 데이터 보강이 추가로 필요하다.
