# ADR 0018: 자료 공급자 상태와 수집 설정을 운용자가 소유한다

- 날짜: 2026-09-09
- 상태: 적용 (1차: 항공기·위성·UAM·지형·건물 · 2차 2026-09-09: 기상(Open-Meteo)과 구름 영상(NASA GIBS) 추가)
- 범위: 수집 정책(무엇을, 얼마나 자주, 어느 범위로, 얼마나 오래)의 소유권, 저장, 검증, wire, GUI. Live Twin 추정, 기체 package, Native FastPhysics/SimpleFlight/Unreal은 건드리지 않는다.

## 문제

수집 정책이 코드와 배포 설정에만 있었다. 항공기 수신 주기·범위·보관 시간, 위성 실시간 요청 여부는 `default.json`과 launcher가 정했고, 운용자가 바꾸려면 파일을 고치고 다시 실행해야 했다. 각 공급자가 지금 무엇을 하고 있는지도 운용 안내 목록에 흘러가는 문구로만 보였다.

## 결정

1. **정책은 User/Application이 소유한다.** `user_application/apps/web_dashboard/library_settings.py`가 기본값(`DEFAULTS`), 한계(`LIMITS`), 필드 서술(`describe_library`), 검증(`validate_settings`)을 갖는다. 순수 모듈이며 인증정보를 다루지 않고 요청도 하지 않는다. 검증 실패는 `source.field: 이유` 형식으로 던진다.
2. **한계는 취향이 아니라 공급자 보호다.** 항공기 30~3600초, 위성 3600~86400초, 보관 60~3600초, 수신 범위 한 변 0.05~25°. 하한보다 잦은 요청은 공용 서비스의 일일 사용량을 태우므로 UI에서도 서버에서도 허용하지 않는다. 기본값은 기존 배포값 그대로다(항공기 45초, 보관 300초).
3. **저장은 Data가 소유한다.** `data/settings/source_settings.py`가 `<workspace>/settings/sources.json`에 검증된 설정만 원자적으로 쓴다. 손상된 파일은 "설정 없음"으로 보고 기본값으로 시작한다. 수집이 파일 때문에 멈추면 안 된다.
4. **정책은 다시 시작하지 않고 적용된다.** `LibraryPolicy`를 수집 루프가 매 주기 읽는다. `enabled`가 꺼지면 그 source는 `paused` 상태로 쉬고, `poll_seconds`는 다음 주기부터, 보관 시간은 구독으로 `LiveSynchronizer.retention_seconds`에 바로 반영된다. 항공기 수신 범위는 "지도 화면 따라가기"가 켜져 있고 화면이 보고한 창이 있을 때만 화면을 따르고, 꺼지면 설정한 범위만 쓴다.
5. **위성 실시간 요청은 기본 꺼짐이다.** 저장된 GP로 계산하는 현재 운용을 유지하고, 운용자가 Library에서 켤 때만 CelesTrak에 요청한다. 배포 설정이 무엇이든 정책이 최종 결정권을 가진다.
6. **API는 버전이 있는 얇은 wire다.** `communication/web/library_routes.py`가 `GET /api/library/sources`(필드 서술 + 현재 값 + 각 source의 현재 상태)와 `PUT /api/library/sources`(부분 갱신)를 제공한다. 검증 실패는 422와 필드명이다.
7. **상태는 실제로 화면을 먹이는 쪽이 말한다.** 위성 실시간 요청이 꺼져 있으면 카드에는 `celestrak`의 중지 상태가 아니라 저장 궤도(`celestrak_saved`)의 상태가 보인다. 지형·건물은 표시 설정이므로 인증 구성 여부를 상태로 보고한다.
8. **자료 하나가 층 하나다.** 카드는 기본으로 접혀 있고 머리글 전체가 버튼이다. 누르면 그 자료의 설정만 펼쳐지고 다시 누르면 닫힌다. 여러 층을 동시에 열 수 있으며, 설정할 것이 없는 자료(UAM)의 머리글은 열리지 않는다(`aria-disabled`). 접혀 있어도 상태 문구는 머리글에 남아 한눈에 읽힌다. 적용 후 다시 그릴 때 열려 있던 층은 열린 채로 남는다.
9. **GUI는 서술을 그린다.** `user_application/web/library_panel.js`는 서버가 준 필드 종류(toggle/number/bounds)만 그리고 규칙을 스스로 만들지 않는다. 바뀐 항목만 보내고, 서버 응답을 새 기준으로 삼으며, 거부되면 입력한 값을 남긴 채 필드명을 보여 준다. 지형·건물은 저장과 함께 지도에도 적용한다.

## 2차 결정 (2026-09-09): 기상과 구름

10. **기상은 값으로, 구름은 그림으로 받는다.** 둘은 하는 일이 다르므로 각각 다른 자료를 쓴다. 값은 Open-Meteo(`communication/external/weather_source.py`), 그림은 NASA GIBS 위성 영상(`digital_twin/visualization/web/cloud_layer.js`)이다. 둘 다 인증키가 필요 없어 인증 관리가 늘지 않는다.
11. **기상은 창 하나를 한 번의 요청으로 묻는다.** 항공기 수신 범위의 중심과 네 모서리 다섯 지점을 좌표 목록으로 한 번에 요청한다. 범위를 넓혀도 요청 수는 늘지 않는다. 받는 값은 구름량(전체·하층·중층·상층), 시정, 바람(속도·돌풍·방향), 기온, 지상 기압이며 바람은 m/s로 받는다. 예보 시계열은 받지 않는다.
12. **읽기는 순수 모듈이 한다.** `digital_twin/live_twin/weather_conditions.py`가 공급자 응답을 typed 관측으로 바꾼다. Data가 기록을 불변으로 얼리므로(dict → mapping proxy, list → tuple) 읽기는 `Mapping`과 `Sequence`로 판별한다. 읽을 수 없는 응답은 예외 대신 빈 지점 목록이 된다. 화면이 나쁜 응답 때문에 죽으면 안 된다.
13. **구름은 표시 자료다.** 서버는 타일을 중계하지 않고 브라우저가 GIBS에서 직접 받는다. GIBS EPSG:4326 타일 격자는 2x1, 3x2, 5x3, 10x5, 20x10, 40x20으로 저해상 단계가 2의 거듭제곱이 아니므로, Cesium 타일 구성은 10x5를 0단계로 삼고 요청마다 3을 더한다.
14. **구름은 회색으로 만들고 어두운 쪽을 걷어낸다.** 세 자료 모두 구름이 밝은 쪽, 지면이 어두운 쪽이다. 채도를 0으로 두어 색 입힌 영상의 색을 없애고, 대비를 올려 구름을 배경에서 떼어낸 뒤 어두운 쪽을 투명 처리한다. 남는 것은 읽을 수 있는 지도 위의 흰 구름이다. 자료마다 대비와 잘라내는 밝기가 달라 각 자료가 자기 값을 갖는다. 기본은 밤에도 보이는 적외다.
15. **최신 슬롯은 GIBS가 고른다.** 정지궤도 자료는 발행이 몇 분 늦어 계산한 시각이 404가 된다(실측: 08:00 정상, 08:10 404). 그래서 시각 자리에 `default`를 쓰고, 갱신 주기로만 바뀌는 버전 값을 질의 문자열에 붙여 주기 안에서는 캐시가 유지되게 한다.
16. **정지궤도 자료는 위성이 보는 범위만 요청한다.** 지구 반대편 타일은 빈 영상이므로 요청하지 않는다. 전 지구 합성에는 이 제한이 없다.
17. **구름 스위치는 두 곳에 있고 한 곳에만 저장된다.** 설정의 구름 토글과 Library의 표시 항목은 같은 값을 가리킨다. 어느 쪽을 눌러도 Library를 통해 저장되고 지도에 적용된다.

## 계층 경계

model_library는 관여하지 않는다(수집 정책은 모델이 아니다). Data는 파일을, Communication은 wire와 외부 adapter를, User/Application은 정책과 화면을 갖는다. 수집 루프는 정책을 읽을 뿐 정책을 만들지 않는다.

## 한계

- UAM은 실시간 공급자가 없어 상태만 보고하고 설정이 없다.
- 지형·건물은 표시 설정이며 서버의 자산 endpoint 구성과는 별개다.
- 설정은 로컬 파일 하나이며 다중 사용자 동시 편집을 고려하지 않는다.
- 상태는 패널을 열 때와 저장할 때 갱신된다. 열어 둔 채로 자동 갱신하지는 않는다.
