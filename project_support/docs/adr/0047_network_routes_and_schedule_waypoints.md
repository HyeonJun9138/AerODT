# 0047. 순항 회랑 양방향과 스케줄 경유점 보존

- 날짜: 2026-09-11
- 상태: 적용
- 범위: Model Library 항로 탐색, 다중 계획 생성, 기존 CSV 실행

## 확인한 문제

실행 중이던 생성 계획 1,811편의 `route_path`가 모두 비어 있었다. 생성기는
`build_plan`의 단계별 시간만 스케줄러에 전달하고, 단계에 들어 있던 경유점은
전달하지 않았다. CSV writer와 reader는 이미 경유점 배열을 지원하고 있었다.

또 계획기의 탐색 그래프는 모든 링크를 단방향으로 취급했다. 사용자가 확인한
의도와 기존 별도 스케줄러의 규칙은 WP 사이 F는 양방향, C/G는 단방향이었다.
지도에 있는 306개 방향 조합 중 292개를 연결 불가로 판정한 뒤, 생성기와 실행기
모두 `allow_direct=True`로 직선 대체 항로를 만들었다. 조종사가 받은 계획 자체가
이륙 연결선을 무시하고 목적지를 향하는 형태였다.

## 결정

1. WP 사이의 F에 한해 탐색 그래프에 역방향 간선을 추가한다. 원본 링크의 좌표,
   고도, ID와 저장 방향을 변경하지 않는다. 명시적 `direction=forward`는 존중하며
   C/G와 FATO 연결을 뒤집지 않는다. 잘못된 것으로 표시된 링크는 탐색에 쓰지 않는다.
2. 생성기는 C/F/G 단계의 전체 경유점 ID를 비행 순서대로 스케줄러에 전달한다.
   단계 경계에서 연속으로 반복된 같은 점만 합친다. CSV의 기존
   `route_waypoint_count`, `route_path` 열을 사용하며 스키마를 바꾸지 않는다.
   식별자 저장은 표시 이름의 중복과 변경에 따른 잘못된 재해석을 줄인다.
   외부 CSV의 표시 이름 배열도 기존과 같이 읽는다.
3. 제공된 `route_path`는 경유 순서가 우선이다. 최단 경로로 다시 계산하지 않는다.
   기존의 명시적 외부 경로 및 임시 지점 호환 처리는 이번 변경에서 확대하지 않는다.
4. 경유점이 없는 구형 CSV는 현재 지도에서 경로를 찾는다. 찾지 못하면 출발하지
   않고 취소 이유를 기록한다. 생성 시에는 해당 방향의 수요를 미운항으로 남기고,
   연결된 조합이 하나도 없으면 적용 전에 오류를 반환한다. 직선 대체는 금지한다.
5. 생성 요약의 `direct_pairs`는 호환을 위해 남기되 0이다. 추가 선택 필드
   `blocked_pairs`로 제외한 방향 수를 표시한다. 단일 계획과 다중 계획은 같은
   탐색 규칙을 사용한다. 명시적으로 요청하는 내부 `direct_path` 시험 도구 자체는
   삭제하지 않지만 사용자 계획 생성 및 시나리오 실행의 fallback으로 사용하지 않는다.

## 적용과 한계

현재 실행의 원본 CSV와 기록은 보존한다. 복구용 새 CSV에는 비어 있는 경유점만
채우며 기체 편성, 출발/도착 시각과 기존 경로는 바꾸지 않는다. 따라서 이 복구는
길어진 항로에 맞춘 스케줄 재최적화가 아니다. 새로 생성하면 실제 연결 항로의
길이와 단계 시간으로 다시 스케줄링한다.

공통 native 조종사, FastPhysics, SimpleFlight, 시각화 보간은 변경하지 않는다.
경로의 존재와 순서 전달 검증은 실제 항적의 회랑 내 제한, 충돌 안전, 경유점 고도의
정확한 달성이나 Unreal 통합 검증과 별개이다. 실제 항적의 횡방향 오차도 측정하여
근거에 남긴다.

재현 도구: `project_support/tools/web_visualization/network_route_check.py`.
