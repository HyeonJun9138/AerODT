# ADR 0035: 버티포트 운영자 화면과 운영 연습의 경계

- 날짜: 2026-09-10
- 상태: 적용. 실시간 자원 제어 및 PSU 통신은 미연결.

## 결정

Stakeholders의 UAM/버티포트에 저장된 설계, 주변 기상, 운항 시간표와 별도 하단
운영 패널을 제공한다. `VertiportPanel`은 응용 화면이며 실제 자원 상태의 소유자가 아니다.
`vertiport_operations.js`는 명시적 예시 일정의 표시 투영과 로컬 보고 초안만 계산한다.
Runtime, 비행계획, 실행 기록 및 조종사 목표를 수정하지 않는다.

- 설계는 기존 `/api/simulation/vertiports`를 읽는다. SVG는 layout의 미터 좌표와
  실제 Gate/FATO/charger/edge 식별자를 그대로 사용한다. 항로 설계나 간격을 다시 생성하지 않는다.
- 시점 선택은 지구 가림과 화면 밖을 제외한 버티포트 중 화면 중앙에 가장 가까운 하나를 선택한다.
  지형/건물 단위의 깊이 가림 검사는 아니며 화면 중앙에 시설이 없으면 임의의 먼 시설을 고르지 않는다.
- 점유와 시간표는 현재 KST 기준의 예시 일정임을 명시한다. 일정은 시간대/시설별로 캐시하며
  실제 layout의 Gate-FATO 연결 경로에만 유도로 구간을 만든다. 예시 표시를 끄면 미연결 상태다.
- 폐쇄/재개는 페이지 세션의 운영 연습 입력이다. 실제 예약을 취소하거나 기체를 이동시키지 않는다.
  점유 중 폐쇄는 점유 정보를 보존하면서 조정 필요로 표시한다. 각 시설의 초안은 분리한다.
- PSU 보고는 가용 현황/도착 순서 조정/시설 제한/재개 네 종류의 로컬 초안이다.
  미전송 상태만 기록하며 접수, 허가, 완료를 만들어내지 않는다. 새로고침하면 초기화된다.
- 비행 컨트롤과 독립적으로 접기/닫기를 지원한다. 운영 패널을 열면 비행 바는 접고
  측정된 높이만큼 위로 배치한다. 비행 재생을 정지하거나 시계를 변경하지 않는다.

## 기상 wire 확장

기존 Open-Meteo 수집의 current 목록에 `weather_code`를 추가하고 `/api/live/weather`
schema_version 1의 각 point에 같은 이름의 선택적 숫자 필드를 추가한다. 없으면 null이며
기존 캐시와 소비자는 그대로 유효하다. 운량만 있는 과거 자료는 맑음/구름을 추정이라고 표시하며
비/눈을 임의 추론하지 않는다. WMO 코드 대응은 https://open-meteo.com/en/docs 기준이다.

새 외부 요청 경로는 없다. 기존 5개 광역 표본 중 가장 가까운 것을 사용하며 표본 거리,
자료 시각, 1시간 이상 지연 여부와 기상 수신 실패를 표시한다. 현장 센서나 항공 기상 관측이
아니며 지상 10 m 모델 바람은 참고용이다. 새 필드 수집에는 서버 재시작과 다음 수집이 필요하다.

## 후속 연결 조건

실시간 자원 모델을 붙일 때만 Runtime이 실제 점유와 예약의 권위자가 된다. 운영자 입력은
검증 가능한 typed 요청으로 전달하고 화면은 그 응답을 읽는다. PSU 메시지는 발신/수신 시설,
correlation ID, 만료, 리비전과 승인 범위를 갖는 계약으로 대체한다. 이번 초안 목록을 실제
전송 큐나 실시간 상태로 승격하지 않는다. 실제 비행계획의 날짜/예약 연결도 별도 작업이다.
