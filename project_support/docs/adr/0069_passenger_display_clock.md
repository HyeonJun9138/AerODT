# ADR 0069: 탑승객 표시의 공통 시계

- 상태: 적용, 2026-09-11
- 배경: 탑승객은 1.5초 HTTP 응답 두 개로 별도 속도를 추정해 외삽했다. 새 응답에서 위치가 되돌아가고 느린 요청이 중첩될 수 있었다.
- 결정: scenario passenger 응답 schema_version 1에 선택적 state_time(UTC Unix seconds)과 scenario_id를 추가한다. 기존 time_s(운항일 초) 및 aircraft 계약은 유지한다. Session이 잠금 안에서 상태/epoch를 함께 읽으며 모델이나 운항을 진행시키지 않는다. 공유 Physical 관측 mixin에는 변경하지 않는다.
- 표시: timestamp가 있으면 보행 경과를 기체와 동일한 표시 시계로 구한다. 동일 보행의 반올림 교정은 역행시키지 않고 epoch 변경은 새 보행으로 초기화한다. 현재 표시 epoch와 다른 응답, 이전 시각 응답을 적용하지 않는다. 요청은 한 개로 제한하고 닫기 이후 늦은 응답을 폐기한다.
- 호환: 구서버의 timestamp 없는 응답은 기존 제한 외삽으로 처리하되 같은 보행 역행을 제한한다. 완전한 공통 시계 적용에는 웹 서버 재시작과 프런트엔드 새로고침이 필요하다.
- 제한: 화면 표시용 보간이며 탑승 완료/비행 허가/실제 사람 상태를 수정하지 않는다. 진행 중인 서버는 자동 재시작하지 않는다.
