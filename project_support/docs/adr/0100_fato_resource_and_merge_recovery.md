# ADR 0100: 빈 FATO 재사용과 접근점 복귀의 소유권

후속: 정지한 복귀 기체의 전체 미래 경로 보호 조건은 ADR 0102로 보완한다. 실제 감속 명령, 접근 허가, 패드 및 주기장 소유권은 유지한다.

## 관측

2026-09-16 운영 실행의 06:49:53 표본에서 마곡(VP015)은 FATO 네 개가 모두 이착륙 겸용이고, 주기장 12개 중 관측 점유는 5개였다. FATO별 연결은 있지만 네 FATO가 두 항로 진입점을 공유한다. 당시 도착 대기편들은 같은 북측 진입점으로 복귀하고 있었다. 06:49 표본에서 복귀 중이던 UAM0044가 06:53 표본에는 다시 원래 대기점에 있었고, 그 사이 다른 도착편이 복귀를 시작했다. 따라서 빈 패드 개수만으로 실제 병목이나 독립 운항 가능 수를 판단할 수 없다.

## 결정

1. 주기장에 있고 출발 허가가 아직 없는 편의 진입 시각 예약은 출발 FATO의 불변 실행 권한과 구분한다. 선택한 출발 FATO가 막혔을 때 연결된 빈 대체 FATO를 재평가한다. 도착 FATO, 예약 순서, 원본 계획, 실제 위치는 그대로 두고 변경된 출발 경로의 진입 예측을 기존 admission 경로에서 재확인한다. 출발 허가 이후 또는 실제 지상 이동 및 비행 중에는 재배정하지 않는다.
2. 이 최적화에서 다른 FATO라는 이름만으로 공용 상승/합류 경로를 독립 자원으로 가정하지 않는다. 대체 경로가 진행 중인 출발 경로와 겹치면 재배정하지 않는다. 정적 분리 완화 설정을 끄거나 켜는 변경 없이, 새 병행 출발을 추가하는 데 필요한 조건만 강화한다.
3. 이미 허가받은 대기점 복귀가 일시적인 주변 교통 때문에 막히면 고정된 관측 위치를 감속 목표로 사용하고 복귀 경로 예약을 유지한다. 매 틱 정지 목표를 다시 옮기지 않는다. 교통이 해소되면 같은 복귀를 계속한다. 지상 출구, 최종 패드, 접근 경로 권한을 잃은 경우에는 기존 대기점 복귀 절차를 유지한다.
4. 사전에 계획된 대기점에서 중간 접근점으로 복귀할 때는 20 m 이내의 제한된 통과 영역에서 native 조종사에게 제어를 넘길 수 있다. 짧은 전후 구간에서는 영역을 더 줄이며, 고도차 3 m 미만, 접근 속도 이하, 낮은 수직 속도와 수직 로터 자세가 필요하다. Python은 WP 인덱스나 물리 상태를 변경하지 않는다. 최종 착륙점에는 적용하지 않는다.

## 계약과 검증

`holding_assignment` 자유 형식 진단 객체에 선택적 `return_hold` 좌표가 들어갈 수 있다. 이는 감속 목표이며 관측 현재 상태가 아니다. 기존 `state=returning`, 이동 경로의 `movement_target`, 다른 필드는 유지한다. 새 필드가 없는 기존 기록도 읽을 수 있다. 외부 요청/API와 기본 정책, 물리 적분 순서는 변경하지 않는다.

신규 회귀 11건, 인접 회귀 및 FastPhysics/SimpleFlight 실제 비행 시험으로 검증한다. 초기 후보는 공용 출발 합류에서 기존 30 m 시험을 깨뜨려 폐기했고, 공용 합류 검사를 추가한 최종 후보에서 해당 시험을 다시 통과했다. 독립 8대/4-FATO 비교에서 양쪽 모두 8편 완료, 대기·복귀 누계는 2,853초에서 2,523초로 감소했다. 전체 완료 시간은 1,949초에서 1,941초로만 감소하므로 전체 처리 용량이 12% 증가했다고 해석하지 않는다. 반복 회귀에서 기존 지상 시험 1건 실패는 수정 전 코드에서도 같은 `land` 응답으로 재현했다.

운영 실행을 수정하거나 재시작하지 않았다. 6,688편 전체 장시간 재실행, 실제 마곡에서의 수정 후 화면, Unreal 실행은 검증하지 않았다. 네 FATO가 항상 동시에 착륙 가능하다는 보장은 하지 않는다.
