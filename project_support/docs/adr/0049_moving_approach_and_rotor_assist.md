# 0049: 이동 접근, 독립 속도 목표와 소각도 로터 보조

날짜: 2026-09-11

## 배경과 승인

역천이 후에도 감속용 속도를 그대로 사용하고 진입점에서 정지를 요구해,
접근이 느리거나 이미 지난 WP로 돌아가는 문제가 있었다. 사용자는 수평
접근 목표 10 m/s와 수직 강하율 500 ft/min을 분리하고, 실제 속도 추종까지
보정하도록 요청했다. 공력을 유지한 기준 AirTaxi는 로터가 수직일 때 몸체
피치 25도 한계에서 약 6 m/s로 제한됐다. 사용자는 멀티로터 제어를 유지하는
전방 10~14도 소각도 로터 보조를 명시적으로 승인했다.

## 결정

- `RoutePilot`은 기존 경유 순서와 물리 관측을 유지한다. 접근 진입점과
  중간 접근점에는 제한된 전방 통과 판정을 적용한다. 마지막 FATO 상공의
  정밀 호버와 수직 착륙은 완화하지 않는다. 가장 가까운 WP를 재선택하거나
  원본 경로, 고도, 현재 위치를 덮어쓰지 않는다.
- 역천이 뒤에는 지난 진입점으로 돌아가지 않고 다음 접근 구간으로 이동한다.
  실제 로터가 수직이고 속도와 수직 운동이 안정되면 강하를 시작한다. 그동안
  유지하는 것은 관측 위치의 복제 상태가 아니라 포착한 고도 **목표**다.
  외부 대기 해제 시 이 목표와 안정 판정을 새로 설정한다.
- 접근 수평 목표 기본값은 10 m/s, 강하 상한은 2.54 m/s다. 두 설정은 독립이다.
  짧고 가파른 구간은 기존 경로에서 제한 강하율을 지키도록 수평 속도를 낮춘다.
  10 m/s를 모든 접근 기하에서 보장하지 않는다. 마지막 착륙률 1.2 m/s와
  기존 수직 이륙 2 m/s는 그대로 두며, 강하 설정으로 이륙을 가속하지 않는다.
- 속도 목표 제어의 Z축 PID는 NED 수직속도를 사용한다. 피치한 몸체 좌표의
  수평 오차가 추가 상승 추력으로 섞이던 문제를 제거한다. 기존 position
  목표 제어 경로는 변경하지 않았다.
- AirTaxi 모델 패키지의 XY 속도 적분을 0.04로 둔다. 비활성 고정익/천이
  동안 XY 적분을 초기화하며, 조건부 적분으로 출력 포화 방향의 누적을 막는다.
  `PidParameters.conditional_integration`의 기본값은 false여서 legacy PID
  수식과 다른 모델은 종전 동작을 유지한다.
- 고정익의 고도 오차 보정을 접근 보정과 분리해 기본 gain 0.7로 둔다.
  수직속도와 가속도 제한은 유지한다. 새로운 bank 기반 협조선회 제어를
  구현한 것은 아니며, 기존 고정익 제어의 작은 고도 추종 지연을 줄인다.

## 보조 틸트와 제어 경계

`VelocityYawAngleGoalNed.allow_rotor_tilt_assist`는 기본 false인 허용 의도다.
안정이 확인된 이동 접근에서만 true이며, 외부 대기 및 수직 착륙에서는 false다.
각도는 조종사가 아니라 모델 파라미터와 SimpleFlight 제어기가 결정한다.

AirTaxi 패키지는 `MC_TILT_ASSIST_MAX` = 14도(rad 단위),
`MC_TILT_ASSIST_RATE` = 2도/s(rad/s 단위)를 설정한다. 전방 수평 목표의
2~10 m/s 구간에 비례해 보조를 주고, 후방 또는 2 m/s 이하에서는 0으로
줄인다. 하강 속도나 몸체 피치가 전방 보조 요청에 섞이지 않는다. 몸체
피치 한계는 30도, roll 한계는 25도다. 이는 기준 모델 보정이지 제조사
인증 운용한계가 아니다. 질량, 항력, 날개 공력과 FastPhysics 적분은 보존한다.

`ControlAxes.tilt`를 mixer 행렬의 가중치로도 사용하던 결합을 분리했다.
선택적인 `allocation_blend`가 없으면 기존처럼 tilt로 배분하고, 보조 중에는
0으로 두어 multirotor 행렬과 제어 branch를 유지한다. `collective_tilt_only`
동안 나셀의 yaw 차동만 제외하며 rotor torque의 yaw 배분은 보존한다.
허용된 접근이 계속되는 동안에는 전방 투영이 0으로 줄어도 collective를
유지한다. 보조 철회 후 명령이 0이 되면 기존 차동 yaw로 복귀한다.

단일 runner와 다중 bridge는 준비 판정에 모든 실제 나셀 각도의 절댓값 중
최댓값을 전달한다. 양·음 yaw 틸트의 평균 0도를 수직 완료로 오인하지 않는다.
기존 시각화/기록의 평균 틸트 값과 17열 ABI 상태 배열은 유지한다.

2도/s는 **같은 velocity 제어 경로 내 보조 공통 명령의 slew**다. 물리 actuator
응답이나 모든 yaw/flight-mode 전환 속도의 보장이 아니다. 명시적 position 또는
direct 제어로 경로를 바꾸거나 Reset하면 기존처럼 새 명령이 제어권을 대체하고
보조 상태를 취소한다. 그 전환에는 이 slew를 유지하지 않는다. 정상 RoutePilot의
접근, 외부 대기, 착륙은 velocity 경로를 쓰며 착륙 전 실제 수직 정렬을 기다린다.

## 호환성과 설정 적용

Native C ABI는 3이다. 기존 tuning 배열 첫 15개 순서와 짧은 prefix를 유지하고
16번째에 `approach_horizontal_speed_mps`, 17번째에 `wing_altitude_gain`을 붙인다.
새 값을 ABI 1/2에 보내면 조용히 무시하지 않고 재빌드를 요구한다.
기존 untuned 호출은 새 기본값으로 비행한다.

조종사 차트의 저장값은 다음 다중 시나리오/기체 생성에 적용하며, 비행 중인
기체를 다시 튜닝하지 않는다. 단일 runner 역시 공통 조종사의 새 기본값을
사용한다. 단일 CLI에 모든 차트 저장값을 전달하는 기능은 이번 범위가 아니다.
서버 재시작 때 저장값 전체를 읽어 필요한 세 값만 합치고 다른 설정을 보존한다.

## 검증과 한계

관측 상태 기반 단위시험, PID 포화와 좌표계 회귀, 개별 나셀 mixer 검사,
actual native 장/단거리 접근, 4 m/s 설정 추종, 좌우/S/교차/급각 선회,
단일/다중 일치, 저장 노선과 100대 시나리오를 검사한다. 수치 및 명령은
개발 로그 evidence에 남긴다. 화면 보간으로 검증 수치를 만들지 않는다.

고도/회랑/충돌 안전성이나 제조사별 물리 정확성을 보증하지 않는다. 급각에서는
우측 항로를 잠시 벗어날 수 있고, 실제 관성에 의한 짧은 방향 보정도 남는다.
Unreal 실제 실행은 별도 검증이 필요하다.
