# ADR 0045 — 다중 비행의 데크 높이 기준과 지도 접지

- 날짜: 2026-09-11
- 상태: 채택

## 문제

다중 비행의 고도는 서버 Local DEM을 기준으로 계산하지만 지도는 사용자가 선택한
World Terrain, Local DEM 또는 타원체를 쓴다. 버티포트의 상면도 해당 지도 지형의
최고점, 평균점, 최저점 또는 수동 높이로 배치된다. 두 공급자의 높이가 다르면
정상적인 Gate 위치의 기체도 데크 아래에 잠기거나 공중에 떠 보인다.

## 결정

Live v1의 `TwinEntity`에 선택 항목 `surface_reference`를 추가한다. 값은 불변
`SurfaceReference(vertiport_id, altitude_m)`이며 `altitude_m`은 시뮬레이션이 실제로
사용한 데크 상면의 WGS84 타원체 고도(m)다. 기존 고도, ECEF 위치, 자세, 기록은
변경하지 않는다. 이전 수신기는 새 필드를 무시할 수 있고, 값이 없는 이전 송신기의
상태는 보정 없이 종전대로 그린다.

ScenarioSession은 출발지와 도착지 중 현재 위치에 가까운 데크의 기준을 내보낸다.
비행 단계만으로 고르면 보간 중인 이전 위치에 새 단계의 데크가 적용될 수 있으므로
위치와 같은 시간의 참조를 DisplaySamples의 기존 유한 링에 함께 보관한다.
별도의 현재 상태 저장소나 비행 로직은 추가하지 않는다.

EntityScene은 해당 참조와 실제 배치된 VertiportLayer의 상면 차이만 표시 위치에
더한다. 지상과 데크 위 10m까지는 전량 적용하고, 데크 위 150m 또는 플랫폼 외곽
반경에서 250m 밖이면 보정량이 0이 된다. 그 사이는 smoothstep으로 연결한다.
높이 차이가 큰 지역은 수직 혼합 구간을 자동으로 늘려 상승 중 표시 고도가 역행하거나
데크를 통과하지 않도록 한다.
지리좌표의 고도 성분만 바꾸므로 위경도는 보존한다. 미배치 데크나 참조가 없으면
추측하거나 다른 건물에 붙이지 않는다. 탑승객도 같은 표시 데크 높이를 사용한다.

5종 비행 GLB의 바닥 기준과 축, 크기는 그대로 둔다. 데크 페인트가 상면보다 2cm
높으므로 접지 표시 여유는 상면에서 3cm다. 모든 기체에 미터 단위의 임의 보정을
넣거나, 지형 충돌을 감추기 위해 depth test를 끄지 않는다.

## 경계와 한계

- 보정은 시각화 책임이며 물리, 경로, 충돌 판정, PSU 판단에 역으로 전달하지 않는다.
- 서버 상태가 본래 지표 아래인 잘못된 궤적 자체를 고치는 기능은 아니다.
- 순항 항적과 계측 고도는 원래 시뮬레이션 기준을 유지한다. 정밀 비교에는 서버와
  클라이언트의 지형 공급자와 수직 기준을 통일해야 한다.
- 매 프레임 네트워크 조회나 전체 버티포트 도형 재생성을 하지 않는다.
- Worker의 v1 전송 코덱은 참조의 변경분만 전달한다. null인 일반 항공기와 위성을
  포함해 기존 빠른 복원 경로를 유지하며, 구형 송신기도 그대로 지원한다.
- 새 참조를 받으려면 기존 서버를 재시작해야 한다. 실행 중인 공유 세션을
  자동 재시작하거나 재생성하지 않는다.

## 검증

`test_surface_reference.py`, `browser/deck_alignment.test.mjs`,
`browser/mission_paths.test.mjs` 및 `deck_alignment_check.html`에서 기준 전달,
높은/낮은 지형, 수동 높이, 보간 시각, 초기 접속, 모델별 접지와 상태 보존을 확인한다.
실행 결과와 범위는 개발 로그에 별도로 남긴다.
