# ADR 0041 — 배속 시계, 병렬 물리 계산과 상태 전달

- 날짜: 2026-09-10
- 상태: 채택
- 관련: ADR 0040 native scheduled route pilots

## 문제

표시 보간은 서버 시계가 실시간과 같은 속도라고 가정했고 따라잡기도 최대 2배속이었다.
따라서 10배속 데이터는 전송 지연으로 오인되거나 긴 단절로 처리되었다. 서버에서는
배속/일시정지 요청도 미처리 물리 시간을 먼저 실행했다. 상태 GET과 World 갱신 양쪽이
tick을 호출하고, 일부 API는 ASGI 이벤트 루프에서 session lock을 기다렸다.

## 결정

1. 정상 운영 tick은 application의 World 갱신 한 곳에서만 실행한다. 상태 GET은 읽기만
   한다. native 제어 요청은 아직 실행하지 않은 wall-clock 차액을 계산하지 않고 마지막
   확정 상태에서 배속을 재설정하거나 멈춘다. 진행 중인 짧은 계산 조각은 먼저 마친다.
2. `ScenarioSession.advance_view`는 worker에서 작은 시간 조각을 실행하고, 동일 lock 안에서
   시각/불변 개체 관찰값/시계 배율을 돌려준다. 한 요청의 최대 진행량은 max(0.25, 배속×0.12)
   simulated seconds다. 과부하 때 wall-clock 기준점을 재설정할 수 있지만 native의 4 ms
   적분 스텝을 건너뛰거나 위치를 직항 보간으로 바꾸지 않는다.
3. `ScenarioPilots`는 독립적인 native 핸들들을 ThreadPoolExecutor로 계산한다. ctypes 호출
   안에서 GIL이 해제된다. 기본 worker 수는 논리 CPU 절반, 최대 8이고 배포 설정
   `scenario_physics_workers`로 1~8을 지정할 수 있다. 각 핸들은 한 스텝에 한 번만 실행된다.
   PSU 판단과 시설 점유 변경은 원래 호출 스레드에서 하고 결과도 고정된 기체 순서로 적용한다.
   다음 논리 스텝 전 모든 Future를 수거한다. 패널 종료/초기화는 풀과 핸들을 해제한다.
   처리 순서가 바뀌어 같은 스텝 안에서 앞 기체의 새 위치를 뒷 기체가 보는 대신, 같은
   이전 스텝 관찰을 토대로 판단한다. 이는 병렬 실행 경계이며 개체 간 물리 충돌 모델은 아니다.
4. 시뮬레이션이 표시되는 동안 World와 websocket 전달 목표는 약 10 Hz다. 위성 등 배경
   계산은 기존 주기(max(0.5초, 설정 tick))를 유지하고 World의 기존 관찰값과 원래 관찰 시각을
   재사용한다. 새 현재 상태 저장소나 화면별 시뮬레이터 인스턴스는 만들지 않는다.
5. wire JSON에 선택적인 `clock_rate`를 추가한다. 없으면 기존 실시간 1, 일시정지는 0이다.
   worker packed header에도 그대로 보존된다. 브라우저는 시계 배율로 정규화한 시간에서
   지연을 추정하고, 따라잡기 속도와 단절 판정도 배율을 반영한다. 시계 전환은 epoch로
   구분하며 배속 변경만으로 위치 ring을 초기화하지 않는다. 시나리오 ring은 32개로 한정해
   감속 직후의 관찰값도 유지한다. 화면은 최신 확정 표본을 넘어 예측하지 않는다.
6. 콘솔과 상단 시계는 지도와 같은 보간 시계를 100 ms 간격으로 읽는다. 배속 요청에는
   즉시 요청 중 표시를 하고, 늦게 도착한 이전 status 응답이 새 배속을 덮지 못하게 한다.
   status 요청은 중첩하지 않으며 닫기 뒤 대기 중인 play가 시뮬레이션을 다시 켜지 못하게 한다.

## 검증

- 100 native pilots × 40초 실험: 1초 계산 평균 직렬 101.27 ms, 4 worker 40.76 ms,
  8 worker 23.84 ms. 비교한 관찰값은 같다. 별도 회귀에서는 서로 다른 초기 yaw를 가진
  8개 핸들을 40회 실행한 모든 상태가 직렬/4 worker에서 정확히 같았다.
- 예시 1,825편/100대 중 15분 워밍업 뒤 12초 동안 10배속 시험: 실제 배속 9.974,
  snapshot HTTP 평균 5.25 ms/95백분위 7.95 ms, snapshot 간격 평균 105.40 ms,
  배속 명령 평균 9.15 ms/최대 18.48 ms. 83대 공중, 물리 실패 0. 외부 실시간 공급자 없는
  격리 TestClient 시험이며 WAN 지연이나 GPU FPS 수치는 아니다.
- Python web_live 788 passed, CTest 18 passed, architecture PASS. Node 전체 780 passed,
  기존 layout.test.mjs의 Simulation preparing 속성 기대 불일치 1 failed. 최종 보간/콘솔
  관련 Node 30 passed. 전체 통과로 기록하지 않는다.
- Chrome/별도 8886 서버에서 100대 예시의 10→1배속, 일시정지 시각 유지, 닫기 확인.
  끝났을 때 native 실패 0, scenario 개체 0. 처음 탭 클릭은 CDP timeout 후 재시도로 확인했다.

## 남은 범위

뷰에 따라 물리 정밀도를 떨어뜨리면 같은 환경을 보는 사용자의 위치에 따라 결과가 달라질
수 있으므로 이번에는 적용하지 않는다. 기존 화면 LOD와 시야 밖 표시 생략은 유지한다.
모든 하드웨어에서 10배속/60 FPS를 보장하지 않으며, 전체 하루 및 실제 Unreal 통합 승인
시험은 별도다. 사용자 8766 서버는 재시작하지 않았으므로 새 코드 적용에 재시작이 필요하다.
