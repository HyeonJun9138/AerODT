# ADR 0107: 조종사 소유 접근 순번 요청 시점

- 상태: 채택
- 날짜: 2026-09-21

## 배경

도착 순번 요청의 발신자는 조종사인데도, 요청 기준시간 판정은
`ScenarioEngine._ask_psu`에 있었다. 수동 조종 화면은 서버 절차와 별도로 브라우저의
도착 거리 기준을 사용해 안내를 만들었다. 이 구조에서는 Simulation이 조종사 절차를
결정하고 자동과 수동의 요청 기준이 달라질 수 있었다.

## 결정

접근 순번 요청 시점은 Pilot이 소유한다. Runtime과 Simulation은 현재 위치, 비행 단계,
도착까지의 예상 잔여시간과 진입점 근접 관측만 제공한다.

- 자동 조종사는 기준 충족 시 `arrival` 요청을 PSU에 즉시 보낸다.
- 수동 조종사는 같은 기준 충족 시에만 접근 순번 요청 버튼을 활성화한다. 활성화
  전 직접 요청은 대기 응답을 받는다.
- 수동 화면은 활성화 전환을 한 번만 알림음과 문구로 알린다.
- PSU는 요청 시점을 만들지 않는다. 요청을 받은 뒤 순번, FATO, GATE와 접근 가능
  여부를 판단한다.
- 브라우저의 거리는 이미 활성화된 안내를 읽기 쉽게 표시하는 자료일 뿐, 요청을
  활성화하는 권한이 없다.

자동과 수동의 기준 입력도 동일한 남은 항로 ETA를 사용한다. 수동 기체는 Runtime의
실제 3차원 위치를 계획 항로의 아직 지나지 않은 구간에 투영하고, 그 지점까지의
복귀시간과 이후 polyline의 구간별 수평속도·상승률·강하율·착륙률을 합산한다.
현재 위치에서 착륙점까지의 직선거리를 요청 기준으로 사용하지 않는다.

기존 `psu.arrival_request_lead_s` 저장값은 읽을 때 Pilot 설정으로 이관한다. 화면에는
PSU 차트에서도 참조값으로 보이지만 단일 소유자는 Pilot이다.

## 기록

자동 요청은 기존 `arrival_request` 운항 이벤트에 `role=pilot`,
`direction=pilot_to_psu`, `request_mode=automatic`을 기록한다. 수동 모드의 기준 도달은
`pilot_arrival_request_ready`를 한 번 기록하고, 실제 버튼 요청은 기존 방향별
Pilot→PSU 메시지 기록을 사용한다.

## 결과

Simulation은 시간을 진행하고 관측을 계산하지만 접근 순번 요청 여부를 결정하지 않는다.
자동과 수동은 같은 Pilot 기준을 사용하며 차이는 자동 전송인지 사람에게 버튼과
알림을 제공하는지뿐이다. 접근 순번 배정은 접근 허가나 착륙 허가가 아니다.
