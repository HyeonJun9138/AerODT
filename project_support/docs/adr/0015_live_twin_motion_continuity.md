# ADR 0015: Live Twin 항공기 운동 연속성과 화면 보간 버퍼

- 날짜: 2026-09-08
- 상태: 적용
- 범위: Live Twin 항공기 추정·보정, WebSocket 스트림 전송 시점, 브라우저 표시 보간. OpenSky 요청 빈도, CelesTrak, Native FastPhysics/SimpleFlight/Unreal, 기체 package, 수집 GLB는 변경하지 않는다.

## 문제

실측(50초, 2026-09-08)에서 OpenSky 수신 간격은 설정 15초가 아니라 약 24.6~25.3초였다(응답 완료 후 15초 대기 구조). 관측의 수신 시점 노후도는 최소 12.7초였다. 추정 유효시간 20초는 다음 수신 전에 만료되어 모든 항공기가 stale로 정지했고, stale 상태에서 새 관측이 오면 항상 discontinuity로 처리해 순간이동했다. `advance_previous`가 discontinuity 플래그를 지우지 않아 절반의 기체에 플래그가 남았고, 브라우저는 그 플래그로 매 스냅샷 보간을 초기화했다.

서버 tick은 1초 설정이지만 이전 상태를 포함한 동기화가 약 1.9초, 인코딩 약 0.45초여서 실제 새 상태 주기는 약 2.4초였다. 1초 스트림 루프는 같은 상태를 두 번 보냈고(중복 프레임), 브라우저는 상태 시간 간격(최대 1.5초 제한) 동안만 보간한 뒤 다음 메시지까지 정지했다. 진행 방향은 새 값으로 즉시 바뀌었다.

## 결정

1. **Live Twin의 제한된 추정.** `constant_velocity_v1`의 `max_extrapolation_seconds`를 60초로 조정한다. 근거는 실측 수신 주기 25초 + 수신 시점 노후도 약 13초, 그리고 한 번의 수신 누락(약 50초)까지 덮되 무한정 늘리지 않는 값이다. 유효시간이 지나면 위치를 고정하고 `quality=stale`로 표시한다. `observation_time`(관측), `received_time`(수신), `state_time`(추정 시각), `valid_until`(추정 한계), `derivation`(observed/estimated)을 계속 구분하며 상세 패널에 수신 시각, 관측 경과, 추정 유효 한계를 표시한다.
2. **연속 보정.** 새 관측은 이전 추정과의 오차를 시간상수 `correction_seconds`(3초)로 점진 보정한다. 실제 서버 tick 약 2.2초에서 한 tick에 약 절반을 옮기는 값이며, 2초로 두면 한 tick에 67%가 이동해 선회 기체의 1~2 km innovation이 급한 미끄러짐으로 보였다. stale이었다는 이유만으로 불연속을 만들지 않는다. 불연속은 (a) 관측 시각 간격이 `max_bridge_gap_seconds`(75초)를 넘는 장기 단절, (b) 오차가 `max_innovation_m + innovation_gap_fraction × 속력 × 관측 간격`을 넘는 큰 위치 오류일 때만 발생하며, 그 tick에서만 `discontinuity=True`를 내고 `continuity_id`를 올린다. 이전 상태를 앞으로 옮기는 경로는 플래그를 항상 지운다. ground track은 359°→1°처럼 짧은 호로 보정하며 속도도 같은 이득으로 혼합한다. track은 자세 측정값이 아니라는 의미(`orientation_source=ground_track`)를 유지한다.
3. **변경 기반 스트림.** `/ws/live`는 새 wire 문자열이 생길 때 깨어나 한 번만 보내고 `stream_seconds`를 최소 간격으로 사용한다. 같은 상태를 반복 전송하지 않으며(keepalive는 10배 간격), 이전 상태 예측을 `predicted_position`으로 단순화해 동기화 비용을 줄였다. 외부 wire v1은 그대로다.
4. **화면 보간 버퍼.** Visualization의 `DisplaySamples`는 entity별 최근 샘플 6개 ring과 도착 창(최근 12개)으로 서버 상태 시각과 도착 시각의 지연 최소값·변동·상태 간격을 추정하고, `gapMax + jitter + 0.25초`를 0.5~5초로 제한한 버퍼만큼 과거를 표시한다. 표시 시각은 최신 샘플을 넘지 않는다(속도 외삽 없음). entity별 표시 시각은 단조 증가하여 뒤로 움직이지 않는다. 중복·역순 스냅샷은 거부하고, 10초 이상 공백(탭 복귀, 서버 재시작)은 재동기화로 처리하며, discontinuity/continuity 변경은 ring을 초기화한다. 진행 방향은 같은 표시 시각으로 짧은 호 보간한다.
5. **시야 기반 갱신 우선순위.** 모델, 선택 대상, 화면상 1px 이상 근접 대상은 렌더 프레임마다, 먼 점은 기존 점 주기(50/100 ms)로 갱신한다. 숨긴 대상의 표시 계산은 기존 분산 LOD 스캔이 담당하며 전체 상태와 카운트는 유지한다.

## 계층 경계

Communication은 전송 시점만 바꾸고 상태를 해석하지 않는다. Data는 원본 기록을 그대로 둔다. Live Twin이 추정·보정·불연속을 결정하고 runtime `TwinWorld`가 유일한 소유자다. Visualization은 수신한 상태를 시간축에서 보간할 뿐 동역학 추정을 만들지 않는다.

## 한계

- 60초 등속 추정은 선회 중인 기체에서 수백 m~수 km 오차를 만들 수 있다. 재생 시험(0.15°/s 선회, 230 m/s)에서 정상 구간 오차 중앙값은 약 190~240 m, 수신 누락 구간 최대 약 1.2 km였다. 이는 관측 재현 정확도가 아니라 표시 연속성을 위한 값이다.
- 수신 시점 노후도가 60초를 넘는 기체(제공자 갱신이 드문 지역)는 도착 즉시 stale이며, 이번 변경으로 해결되지 않는다.
- 서버 tick은 여전히 1초 설정보다 느리다. 오프라인 측정(위성 16,509 + 항공기 10,000)에서 동기화 0.85초 + 인코딩 0.4초이고, 실제 서버(브라우저·probe 연결 포함)에서는 상태 간격 중앙값 약 2.2초였다(이전 약 2.45초). 위성 SGP4와 19 MB JSON 인코딩·전송 비용은 이번 범위가 아니다.
- 표시 지연은 최신 상태 기준 최대 5초, 벽시계 기준으로는 서버 지연을 더한 값이다. OpenSky 요청 빈도 증가와 시야 기반 우선 수집은 다음 단계다.
