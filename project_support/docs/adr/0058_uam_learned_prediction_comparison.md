# 0058 — UAM 학습 모델의 다중 시간 구간 비교

날짜: 2026-09-11

## 결정

사용자가 제공한 원본 forward, route encoder, scaler와 입출력 예제로 단기 10초,
중기 90초, 장기 240초 모델을 연결한다. 새 최상위 폴더나 외부 backend를 복사하지 않는다.

- `ai_pnp/uam_route_model.py`: NumPy 순전파. 실행 중 torch나 pickle을 사용하지 않는다.
- `ai_pnp/uam_features.py`: 학습 원점과 축, 단위에 맞춘 읽기 전용 입력 변환.
- `ai_pnp/uam_prediction.py`: 독립된 세 미래 경로와 최대 8개 결과 캐시. 세 모델 인스턴스를 재사용한다.
- `data/simulation/prediction_history.py`: 최대 8기, 기체당 240표본, 40초 과거 입력 이력.
- `user_application/uam_mission/scenario_session.py`: 선택 관심 대상에 한해 상태와 임무를 같은 잠금 안에서 수집한다. 이후 추론은 잠금 밖 HTTP worker에서 실행한다.
- `digital_twin/model_library`: 모델과 검증 가용성을 선언한다. 계산 객체를 만들지 않는다.
- 웹 시각화: 기존 선택 기체 궤적 채널에 비교 경로와 범례를 추가한다. 예측은 제어 명령이나 현재 상태에 되먹임하지 않는다.

## Wire와 설정

기존 `/api/live/trajectory/{entity_id}`의 학습 UAM 응답만 `schema_version:2`,
`kind:uam_prediction_comparison`으로 확장한다. `entity_id`, `epoch`, `continuity_id`,
`flight_phase`, `generated_at`과 모델별 `predictions`를 포함한다.

각 항목은 모델 ID, 고정 horizon, `ready/warming_up/unavailable`, 준비 이력 길이,
사유, 선택적 path를 갖는다. 성공 path의 `reference_frame`은 `ecef_m`이고
기준시각의 실제 위치 1점 및 예측 25점을 `[absolute_time,x,y,z]`로 전달한다.
세 모델은 같은 현재 상태에서 계산한다. 출력은 기준점 상대 누적 변위이므로
모델이 반환한 절대 ENU를 ECEF로 바꾸며 다시 누적하지 않는다.

비교 모델 ID는 `uam_route_mlp_comparison`이다. 하나 이상의 검증 모델이 있으면
선택할 수 있고 나머지는 항목별 사용 불가로 표시한다. 기존 세 개별 모델 선택도
동일 envelope의 항목 1개로 응답한다. 기존 임무 의도 및 항공기/위성 예측 응답은 보존한다.

`uam_prediction.short_enabled/mid_enabled/long_enabled`는 기본 true이고 표시만 바꾼다.
비교 모드에서는 세 모델을 함께 계산하므로 숨겼다가 다시 켤 때 새 계산을 기다리지 않는다.
기존 기본 선택인 임무 의도 모델 및 사용자 공유 설정은 자동 변경하지 않는다.

청록 실선(+10초), 주황 파선(+90초), 보라 점선(+240초)을 사용한다. 경로를 옆으로
밀거나 움직이는 기체에 붙이거나 모델 간 좌표를 혼합하지 않는다. 갱신은 투명도만 전환한다.
선택, 재생 epoch, 임무 단계, 모델 변경 시 이전 응답을 폐기한다.

### 선택 기체 갱신과 시간 구간 표시 보정 (2026-09-11)

선택 UAM 조회의 목표 간격을 200 ms로 줄이고 지도 표면의 별도 타이머와 분리한다.
한 요청이 끝나기 전에는 다음 요청을 쌓지 않는다. 문맥이 맞지 않는 응답도 재시도
간격을 우회하지 않는다. 표시 시간 이전의 구간만 매 프레임 잘라내고, 경계점은
원본 예측의 이웃 두 표본 사이에서 보간한다. 기준 시각, 미래 끝점 및 원본 좌표는
그대로이며 기체 위치로 경로를 이동하거나 두 추론 결과의 좌표를 혼합하지 않는다.

새 결과는 150 ms 투명도 전환을 사용한다. 모델별 선 두 쌍을 재사용하며 같은
좌표의 반복 응답은 전환을 다시 시작하지 않는다. 선택 해제 및 문맥 폐기 시 모두
제거한다. 정보창에는 표시 시계 기준의 예측 경과, HTTP 왕복 시간과 갱신 지연을
보인다. 정지된 시계에서도 HTTP 실패/새 경로 미수신을 정상으로 표시하지 않는다.
이 경과와 지연은 브라우저의 표시 메타데이터이며 서버 wire schema를 변경하지 않는다.

## 입력과 검증 한계

- short는 0.4초 간격 25점(9.6초), mid/long은 1.2초 간격 25점(28.8초)이다.
- 실제 관찰 범위 안에서만 보간한다. 2.5초보다 큰 틈이나 부족한 이력은 준비 중이다.
- 고빈도 GET도 같은 0.2초 bin의 최신 끝점만 교체하므로 이력 보존 범위를 줄이지 않는다.
- 목표 전환의 목표 벡터, 속도, 횡방향 오차는 이산 처리한다. 자세 보간은 최단 각도와
  원본의 `[-180,180)` 범위를 사용한다.
- 학습 `t`는 실제 off-block 이후 초이며 Unix timestamp나 하루 시각이 아니다.
- 고정 학습 원점은 위도 37.552, 경도 127.0이다. 위도당 111320m, 원점 위도의 고정
  cosine을 쓰는 원본 투영을 그대로 적용한다.
- 현재 SimpleFlight에서 해당 학습 입력 전체가 직접 제공되지는 않는다. 각속도는 자세
  차분, 바람은 0 가정, active speed는 활성 구간 계획 속도로 근사한다. ctrl_00 학습과
  현재 제어기의 차이를 UI와 응답에 명시한다. 이 근사가 실제 유효 제어명령과 같다는
  주장은 하지 않는다. 시나리오 밖 기체나 활성 경로가 없으면 사용 불가다.

가중치, contract와 scalers의 canonical JSON, 실행 구현 파일 해시를 검증 proof에 묶는다.
가중치만 동일한 다른 scaler/시간 계약은 검증된 모델로 인정하지 않는다. 웹 프로세스는
검증되지 않은 패키지를 실행하지 않고 검증 도구만 신규 import를 검증할 수 있다.

원본 예제의 엄격 오차 한계 0.1mm는 단기만 통과하고 중기와 장기는 통과하지 않는다.
현재 환경의 원본 float32 runner 자체도 이 엄격 기준에서 차이가 난다. 원본 float64
forward 및 역 scaler 일치와 별도로 고정 2mm 수치 호환 기준을 적용한다. 허용 오차를
관측 결과에 따라 늘리지 않으며 strict pass/fail을 별도 보존한다. 이것은 구현 재현성
검증이지 예측 물리 정확도나 실기체 적합성의 증명이 아니다.

## 적용 범위

독립 간이 임무 입력에서 실제 세 모델과 HTTP, JS 검증기 및 Cesium 표시를 확인한다.
native 장시간 운항의 예측 오차 및 Unreal 비행은 이번 변경의 검증 범위 밖이다.
사용자 재생 탭과 운영 서버를 재시작하지 않는다. Python 코드 반영은 재생을 끝낸 뒤
서버 재시작이 필요하며 그 후 사용자 페이지를 새로고침한다.
