# ADR 0046 — 단일·다중 비행의 공통 경로 유도

- 날짜: 2026-09-11
- 상태: 채택
- 대체: ADR 0040의 다중 비행 전용 `precision_route` 동작, ADR 0043의 별도 순항 분기

## 문제와 결정

두 실행 진입점은 이미 같은 `RoutePilot`을 호출했지만, 다중 비행만 별도 분기를
켜고 있었다. 이 분기가 초기 방향 정렬 중 목표 높이를 출발 데크로 되돌렸다.
180도 다른 방향에서 출발하는 수치 시험에서 상승과 하강이 반복됐다. 또 순항
경유점은 단일 비행의 60 m 대신 8 m 반경으로 전달됐다. 지나친 점을 다시 잡으려는
선회, 조기 역천이, 저속 회복 잠금이 겹쳐 장시간 순항하지 못했다.

전용 플래그를 제거한다. 배치 실행기와 C ABI 실행기는 동일한 공통 유도를 쓰며,
다중 실행은 기체마다 독립된 조종사와 Runtime을 가진다. 스케줄, PSU 허가, 지상
이동, 기록과 시각화의 소유권은 변경하지 않는다. C ABI 2의 배열 형식도 유지한다.

## 유도 동작

1. 6초 로터 시동 후 출발 방위를 유지하며 수직 상승한다. 지정 호버 높이에 도달하고
   안정된 뒤 그 높이에서 출발 방향으로 정렬한다. 실제 방위와 회전율이 안정돼야
   수평 가속을 시작한다. 한 번 허용한 출발 정렬을 순항 중 다시 적용하지 않는다.
2. 순항 경유점은 통과점이다. 제공된 경로 위의 제한된 전방 지점을 향해 조향하며
   중간 점마다 제동하거나 멀티로터로 정지하지 않는다. 제동 거리 계산은 남은
   고정익 구간 전체를 사용한다.
3. 고정익 통과점의 진행 판정은 수평 위치를 사용한다. 이미 지난 상승 경유점으로
   되돌아가지 않으며 다음 목표를 향해 계획 고도를 계속 추종한다. 실제 고도를
   계획값으로 덮어쓰지 않는다. 따라서 경유점에서 지정 고도가 정확히 달성됐다는
   보증은 아니다. 호버와 착륙은 계속 3차원 위치와 안정 조건을 검사한다.
4. 상승 종료는 수직 감속 거리를 고려한다. 접근에서는 고정익으로 먼저 감속한 뒤
   역천이한다. 역천이 중 수평 속도 명령도 줄여, 수직으로 돌아온 로터에 순항
   속도를 계속 요구하던 문제를 막는다. 실제 틸트가 복귀하고 진입점이 안정되기
   전에는 강하하지 않는 기존 조건을 유지한다.
5. 저속 회복 잠금은 실제 역천이가 완료된 뒤 재허용된다. 고정익 전환을 금지한 채
   고정익 속도가 될 때까지 기다리는 교착을 제거한다. 실제 전환 속도 판정과
   작동기 상태는 여전히 SimpleFlight와 Runtime이 결정한다.

획득 반경 규칙은 Model Library의 `waypoint_capture_m`을 두 진입점이 공유한다.
기존 설정 ID는 유지하되 정밀 반경은 수직 이착륙에만 적용한다. 역천이 설정의
설명과 브라우저 차트 시험 자료도 실제 변경된 동작에 맞춘다.

## 검증과 범위

- 실제 native 회귀시험은 단일/다중 진입점의 전체 궤적을 CLI 출력 오차 0.000051
  이내로 대조한다. 시간 조각을 달리 전달해도 같은 4 ms 물리 궤적을 얻는다.
- 수직 상승의 단조성, 호버 높이에서의 방위 정렬, 짧은 상승과 급한 코너, 순항
  틸트 유지, 역천이와 접지, 기체별 상태 독립성 및 대기 후 재개를 검사한다.
- 저장된 24개 서로 다른 노선이 완료됐고 각 노선의 모드 구간은 멀티로터 → 천이
  → 고정익 → 천이 → 멀티로터였다. 100대 편성의 1시간 native 실행은 137편 출발,
  62편 주기장 도착 완료, 조종사 실행 실패 0건이었다. 전체 하루 완주는 아니다.

경유점 통과와 전방 조향은 코너를 자를 수 있다. 충돌 회피, 회랑 이탈 보장,
고도 제약의 인증, 기종별 제조사 물리 모델, 실제 Unreal 통합 승인을 뜻하지 않는다.
기준 AirTaxi의 관측 고도 오차와 지형·데크 기준 차이는 남는다. 현 작업은 물리
상태를 보간으로 교정하거나 UI를 더 매끄럽게만 보이도록 덮지 않는다.
