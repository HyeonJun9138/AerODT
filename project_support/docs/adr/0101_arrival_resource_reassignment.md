# ADR 0101: 접근 전 FATO와 주기장 묶음 재평가

## 결정

접근 허가가 아직 시작되지 않은 도착편은 같은 버티포트의 연결된 착륙/겸용 FATO와 비어 있는 주기장 조합을 반복 검토한다. 기존 진입점과 이미 비행한 경로를 유지할 수 있는 후보만 허용한다. FATO의 실제 점유와 예약, 공중 경로의 교통, 지상 출구 장애물, 주기장 점유 및 예약을 확인한다. 더 나은 실행 가능한 조합이 있을 때만 변경하며 최종 접근, 이미 시작한 접근, 실패 기체에는 적용하지 않는다.

검토 주기는 시뮬레이션 시간 5초이며 접근 진입점 1.5km 이내부터 적용한다. 후보가 없거나 한 번 재배정한 뒤에도 다음 주기에 다시 평가한다. 현재 조합이 사용 가능하면 예상 주기장 도착 시각이 15초 이상 개선될 때만 변경한다. 서로 다른 진입점으로 되돌아가거나 전역 항로를 다시 만드는 기능은 포함하지 않는다.

후보 경로 및 불변 지상 형상만 재사용한다. 교통, 실제 점유, 예약, 출구 장애물은 매 평가에서 새로 확인한다. 같은 FATO의 공중 경로는 주기장마다 중복 검사하지 않고, 검사 중 native 예측 비행을 생성하지 않는다. 반복 평가의 수치 ETA 변화만으로 운영 결정 로그를 쌓지 않는다.

네이티브 C ABI 6에 `aerodt_pilot_replace_arrival(handle, expected_index, first, points, count, landing_yaw)`를 추가한다. 반환값 1은 성공, 0은 현재 진행 때문에 거부, -1은 오류다. 관측된 WP 인덱스가 일치하고 변경 구간이 현재 목표보다 뒤에 있는 비고정익 접근 suffix일 때만 교체한다. 마지막 두 점은 수직 착륙 열이어야 한다. 물리 런타임, 시계, 조종기 상태, 현재 목표와 지나온 경로는 재생성하지 않는다. 접촉 평면의 목적지도 같은 호출에서 갱신한다. 기존 ABI 1~5 함수와 17개 상태 배열은 유지한다.

ABI 6 DLL은 버전별 파일명으로 생성하여 운영 중인 DLL을 덮어쓰지 않는다. Python은 ABI 6을 우선 발견하되 이전 DLL도 읽는다. 이전 DLL에서는 재배정을 하지 않고 진단 사유를 남긴다. 서버 재시작 없이 진행 중인 실행의 DLL을 교체하지 않는다.

PSU 예약 변경은 새 주기장과 슬롯 확보 후 native 수락을 확인하고 기존 자원을 반환한다. 거부/예외 시 새 임시 예약을 원복하고 기존 경로와 예약을 보존한다. 비행 번호, 요청 순서, 원본 비행계획은 바꾸지 않는다. 후보 판단과 변경 이유는 기존 PSU 결정 이벤트로 기록한다.

## 검증 계획

단위시험은 미래 구간만 교체, 진행 인덱스 경쟁, 최종 접근 거부, 예약 롤백, 빈 FATO/주기장/출구/항로 조합, 반복 평가와 진동 억제를 검증한다. 실제 FastPhysics/SimpleFlight 시험은 같은 런타임에서 목적 패드 변경 후 실제 접지 및 gate_in 완료를 확인한다. 운영 실행/Unreal 검증 여부는 개발 로그에 별도로 기록한다.
