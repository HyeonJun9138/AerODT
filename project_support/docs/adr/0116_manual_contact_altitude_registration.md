# 0116 수동 접촉 좌표와 운항 시뮬레이션 고도 기준 연결

## 문제

수동 native runtime은 세션 시작 때 검증한 contact_decks의 높이에 접촉한다.
자동 운항 엔진은 서버 지형과 시설 높이로 만든 별도의 데크 기준을 사용한다.
기존 _share는 수동 고도를 변환하지 않고 운항 엔진에 게시했다. 이후 항적은
자동 기체와 같은 surface_reference를 받아 표시 보정이 다시 적용됐다.
운항 엔진의 거리 비교에도 서로 다른 기준의 고도가 들어갔다.

## 결정

- 물리 원점, native 접촉면, 조종석 socket sample과 native 실행 기록은 바꾸지 않는다.
- 이미 departure_surface/contact_decks에서 검증한 시설별 접촉 높이를 내부
  place_manual mailbox에 contact_heights로 함께 전달한다. 기존 hello wire 형식은
  유지한다. contact_heights가 없는 기존 내부 호출의 동작도 유지한다.
- manual_takeover.place에서 운항 엔진에 관측을 반영하기 전에 해당 비행의
  출발/도착 중 가까운 데크의 등록 변환을 역으로 적용한다. 식은 시각화의
  deckSurfaceOffset과 대응하며 높이/수평 거리의 smoothstep, 상승 시 단조성,
  표시 도색 여유3cm를 포함한다. 건물/지면으로 무조건 clamp하지 않는다.
- 운항 상태, 항적, PSU 관측, proximity 기록은 그 변환 뒤의 공통 운항 기준을
  사용한다. 표시에서는 기존 전방향 보정을 한 번 적용하므로 원래 수동 좌표로
  돌아온다. 위치와 예측 속도가 다른 기준을 갖지 않도록 NED 수직 속도도 같은
  좌표 변환의 국소 차분으로 바꾼다. 수동 원본 telemetry는 수정하지 않는다.
- 세션이 다음 편으로 넘어가도 그 편의 출도착 시설을 사용한다. 제공되지 않은
  데크나 보정 영역 밖은 임의 지형 높이를 추정하지 않고 기존 고도를 유지한다.

## 한계 및 적용

이는 화면 지형을 서버 DEM으로 설치하는 변경이 아니며, 운항 좌표 등록을
일치시키는 경계 변환이다. 지오이드/타원체의 실제 측지 정확도 보증이나
고도 오차가 없는 지형 데이터 확보를 의미하지 않는다. 높은 데크의 blend 영역은
비선형 좌표이므로 변환된 운항 수직 속도와 원본 native 수직 속도는 다를 수 있다.
브라우저의 지형 소스/시설을 세션 도중 변경하면 native 접촉면도 옛 구성이므로
새 세션이 필요하다. 기존 혼합 기준 항적/과거 proximity 기록은 자동 덮어쓰지 않는다.
서버 재시작 및 새 비행부터 적용한다.

## 검증

- test_manual_altitude_datum.py는 실제 JS deckSurfaceOffset을 호출해 양/음/큰
  높이차, 수평 거리, 상승 구간84조합에서 역변환 오차1e-7m 이내를 확인한다.
- native socket 원본 불변, 운항 상태와 track 일치, 근접 기록 수직차가32.68m
  대신 표시 여유3cm 수준, 출발/도착/다음 편, 높은 순항 불변, NED 변환을 검사한다.
- 관련10개 Python 시험 파일77 PASS. 실제 사용자 비행/화면 검증은 별도로 필요하다.
