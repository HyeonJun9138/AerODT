# ADR 0070: 사용 가능한 게이트·지상 출구를 반영한 도착 순서

- 상태: 채택 / 2026-09-11

## 문제

빈 게이트가 있어도 다른 기체의 임시 예약, 예정 게이트까지의 유도로 장애물, 연속 출발의 교차 경로 예약 때문에 체공이 길어졌다. 기존 게이트 재배정은 주기 상태의 장애물만 재평가했고, 지상 이동 중인 선행편이 수 분 뒤 도착 전에 빠질 수 있어도 접근 전체를 막았다. 사용할 수 없는 선행편의 예약 슬롯도 후속편보다 먼저 유지됐다.

## 결정

1. Simulation과 Physical이 사용하는 `ScenarioEngine`/`PsuSequencer`만 수정한다. 센서 보간, 기체 위치, 조종사 상태를 임의로 바꾸지 않는다. 수신 Twin은 전달된 운영 관측과 판단 이력을 표시한다.
2. 실제 비어 있고 예약 가능한 게이트 중 현재 FATO에 연결되며 출구가 확보되는 경로를 고른다. 막힌 이동 기체도 재배정 사유다. 원래 계획은 보존하고 실제 게이트·유도로·하차 동선은 원자적으로 변경한다. 이미 지상에서 이동 중이거나 native 최종 정렬에 들어간 기체의 경로는 변경하지 않는다. 재배정 해제 시에도 예정 게이트가 비면 다시 확보한다.
3. 지상 출구를 확보하지 못한 미접근편은 임시 게이트 예약과 미래 패드 슬롯을 반환한다. 대기 번호는 보존한다. 이미 접근을 시작한 기체의 게이트와 실제 지상 점유는 반환하지 않는다. 출구가 준비되지 않은 요청은 준비된 후속편의 접근 개시를 막지 않는다.
4. 예측 접근에서는 관측상 이동 중인 입항 지상 기체의 현재 경로와 이동권을 읽는다. 전체 교차 구간을 벗어날 지점까지 이동권이 있고, 최종 게이트가 그 구간 밖이며, 곡률/가속 여유/ETA 여유를 포함해 도착 전 이탈할 수 있을 때만 접근을 허용한다. 정지·실패·이동권 누락·구간 안에서 끝나는 경로에는 이 예측을 적용하지 않는다. 최종 진입 시에는 실제 패드·출구·선행편을 다시 검사한다.
5. 착륙/혼합 간격 이상 실제 체공한 도착편이 게이트·출구를 확보하면 새로운 교차 출발보다 우선한다. 사용할 수 없는 도착편 때문에 지상 출발까지 막지는 않는다. 아직 시작하지 않은 출발 예약은 실제 빈 시간으로 갱신하며 중복 슬롯을 만들지 않는다. 실제 점유와 교차 경로 보호는 계속 적용한다.
6. PSU Decision Chart와 대기 사유를 실제 분기에 맞춘다. 교통 분리 때문에 멈춘 항공기에 단순히 ‘접근 진행’이라고 표시하지 않는다. HTTP/wire schema와 센서 수신 그룹은 변경하지 않는다.

## 검증과 한계

게이트 재확보·임시 예약 반환·준비되지 않은 선두 요청·이동권 기반 출구 예측·최종 실제 점유·장기 대기 도착 우선·출발 슬롯 갱신을 회귀시험한다. 저장된 100대/18시설/1,825편 계획을 실제 native 조종사로 독립 재생해 전후 비교한다. 결과와 실행 적용 상태는 개발 로그의 capacity_recovery 증거에 기록한다.

계획의 수요가 실제 게이트/접근 용량을 넘거나 지상 경로가 물리적으로 막혔으면 대기는 남는다. 비어 보이는 이륙 전용 FATO를 착륙용으로 바꾸거나, 비행 중 FATO·접근 항로를 강제로 바꾸지 않는다. 예측은 운영 의도이며 미래 위치나 최종 착륙 허가가 아니다. 단일 기본 Unreal 임무 검증을 100대 전체 Unreal 장면의 증거로 취급하지 않는다.
