# 0056: 버티포트 시점 이동의 모델 사전 준비

날짜: 2026-09-11

## 결정

LiveGlobe.flyToVertiport는 카메라 이동을 시작하기 전에 목적지 반경
1.5km의 가까운 UAM/항공기 최대 8대를 준비 대상으로 고른다.
DestinationPreparation은 EntityScene의 최신 위치를 참조하고 렌더링
우선순위만 소유한다. 숨긴 레이어, 미등록 자산, 실패한 모델은 제외한다.
GPU 로드 동시성은 기존 movingModelLoads/modelLoads 예산을 유지한다.
준비 중인 모델은 렌더링 캐시 정리로 즉시 제거하지 않는다.

LiveGlobe 생성 옵션에 선택적인 onDestinationPreparation 콜백을 추가한다.
이는 웹 화면 내부 계약으로 moving/preparing/ready/timeout/cancelled 및
선별 대상의 ready/total 수를 전달한다. wire schema는 변경하지 않는다.
준비 완료는 glTF 응답 수신이 아니라 Cesium GPU 모델과 텍스처 준비 상태다.
준비 전에는 기존 기체 billboard를 표시하고 근거리에서 28px로 보강한다.
정밀한 기종별 저해상도 3D 메시를 새로 만드는 방식은 아니다.

User/Application의 DestinationLoading은 도착 후 준비가 남을 때만 지도를
옅게 덮고 진행 상태를 보여 준다. 입력을 차단하지 않으며 최대 5초 후
해제한다. 카메라 이동 콜백이 오지 않을 때에도 8초 watchdog으로 정리한다.
표시가 사라져도 일반 모델 로딩은 계속되며, 실패하면 기존 대체 표식을 쓴다.
빈 목적지는 데이터가 늦게 도착할 여유 600ms를 둔 후 표시를 해제한다.

연속 이동은 토큰으로 구분하고 이전 콜백을 무시한다. 캔버스 조작, 휠,
줌 버튼/슬라이더, 다른 객체 추적 및 화면 파괴는 이전 목적지 준비를 취소한다.
취소할 때 완료된 모델 캐시를 파괴하지 않는다. 시뮬레이션 상태, 재생 시각,
외부 데이터 수신 정책 및 비행 명령은 변경하지 않는다.

## 검증과 한계

Node 회귀와 독립 Cesium QA에서 준비 순서, 대체 표식, 자동 해제, 취소를
검증한다. QA는 시험 위치/기체를 사용하며 운영 시나리오를 시작하지 않는다.
최대 8대가 준비되어도 주변 모든 기체/지형/영상/건물이 완료됐다는 뜻은 아니다.
제공자 데이터가 아직 도착하지 않은 경우 가짜 기체를 만들어 표시하지 않는다.
네트워크 캐시, GPU, 지형 및 동시 실행 부하가 달라지므로 특정 속도 향상을
모든 버티포트에 보장하지 않는다.
