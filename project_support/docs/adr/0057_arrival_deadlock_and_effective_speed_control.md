# ADR 0057: 접근 교착 해소와 실제 속도 기준 교통 감속

Date: 2026-09-11
Status: Accepted

## 관측한 문제

실행 중인 1,584편 계획에서 천호 도착편들이 공통 접근 지점에 정지했다. UAM0066↔UAM0072처럼 이전 양보 지시가 서로를 기다리는 고리를 만들었다. 정지 뒤 전방 판단에 사용할 속도가 없어도 기존 yield를 계속 유지했고, 교통 대기는 별도 대기 지점 대신 현재 위치를 목표로 삼았다. 선행편이 주기장 예약을 점유한 채 멈춰 후속 슬롯의 ETA도 계속 밀렸다. 대기 구역 포화 시 기존 자리를 재사용하는 문제도 있었다.

순항에서는 계획 속도가 실제 달성 속도보다 높을 때 감속 계수를 적용해도 실제로 거의 느려지지 않았다. 동일 항로의 두 기체에 같은 우측 이동을 주거나, 교통이 남아 있는데 복귀 지시로 바뀌는 문제도 확인했다.

## 결정

- 접근 교통의 우선순위를 최종 착륙, 접근 개시 시각, 요청 시각, 순번, 기체 ID로 일관되게 정한다. 정지한 기체도 같은 순서를 사용한다. 후속편은 회랑 밖의 독립된 대기 목표로 이동하고 선행편은 실제 분리가 확인될 때까지 감속한다. 최종 구간은 현재 위치에서 감속해 뒤쪽 접근을 가로지르는 복귀를 피한다.
- `instruction.action`에 `wait_clear`를 추가한다. 이는 선행편의 분리 확인 대기이며 최종 착륙 허가가 아니다. 기존 `yield`는 후속편의 양보이다. PSU Control Panel과 조종사 판단 요약이 두 사유를 일반 슬롯 문구보다 우선 표시한다. 같은 패드의 막힌 선행편도 명시한다. ABI와 API schema 버전은 유지하며 기존 instruction 객체의 action 값만 확장한다.
- 대기 위치는 회랑을 피하는 방위에 수평으로 먼저 분산하고 층을 사용한다. 모두 차면 외곽 고리를 추가하며 점유된 슬롯을 재사용하지 않는다. 내부 슬롯은 `(방위, 층, 고리)`이며 이전 2원소 슬롯도 해석한다.
- 동일 방향 순항에서는 후속편이 감속한다. 교통이 해소되기 전 기존 우측 편차를 갑자기 지우지 않는다. 실제 경로 편차를 읽어 이미 이동한 폭을 새 회피 여유로 중복 계산하지 않는다.
- native RoutePilot의 교통 감속은 `min(계획 속도, 실제 수평 속도)`를 기준으로 한다. 기존 계수 범위, 고정익 회복 여유, native 가감속 제한 및 C ABI 4를 유지한다. 위치·고도·임무 진행을 직접 쓰지 않는다.
- 이륙은 실제 배치가 가까운 다른 패드의 접근도 보호한다. 출발 패드 해제는 단계 이름만 보지 않고 실제 수평 이탈 거리를 확인한다. 착륙 최종 진입도 가까운 출발 패드의 활성 점유를 확인한다. 멀리 떨어진 패드는 독립적으로 운용할 수 있다.

## 검증과 적용

초기 접근 교착 회귀 4개와 native 감속 회귀가 기존 코드에서 실패하는 것을 확인했다. 최종 Python/native 통합, Node 차트·관제·조종사 시험 및 CTest 결과는 development_log의 해당 작업 evidence를 따른다. 원격 사용자 서버에 접속해 읽은 계획을 독립 native 프로세스에서 100대/70분 실행하고 기존 코드와 비교했다. 실행 중인 사용자 시나리오를 테스트 대상으로 중단하지 않았다.

## 한계

70분 비교는 전체 운항일이나 충돌 안전성 인증이 아니다. 최종 생성 계획 재현에서도 수평·수직 각각 15m 미만의 짧은 근접 2쌍(2초/1초)이 남았다. 장시간 접근 중첩은 해소됐지만 항로 교차의 단기 선형 CPA와 실제 선회 궤적 차이는 추가 보완 대상이다. 독립 재현은 서버 지형 높이를 가져오지 않은 기준 AirTaxi 물리이며 실제 Unreal 충돌 sweep/영상 검증은 수행하지 않았다. 물리적으로 모든 주기장이 차면 후속편의 대기는 정상적으로 유지된다.
