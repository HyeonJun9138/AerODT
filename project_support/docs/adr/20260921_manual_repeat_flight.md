# 수동 배정 기체의 다음 예정편 연속 운항

## 배경
수동으로 배정받은 기체는 GATE 도착 보고까지 정상적으로 하루 운항에 반영됐지만, 조종석에는 완료한 비행편만 남았다. 같은 기체의 뒤 일정이 이미 편성돼 있어도 충전 중에는 그 정보를 확인할 수 없었고, 지상 절차가 끝난 뒤에는 세션을 닫고 다시 배정될 때까지 기다려야 했다.

## 결정
다음 비행은 새로 만들지 않고 `ScenarioEngine`이 소유한 해당 기체의 기존 `flights[next_flight]`만 읽는다. GATE 도착 보고가 완료된 뒤 advisory에 `next_flight`와 `remaining_flights`를 추가한다. `next_flight`에는 편명, 출발지, 목적지, 계획 출발 시각, 회항 준비 시각, 배정 FATO와 GATE, 탑승객 수, 충전 목표를 포함한다.

수동 WebSocket은 배정 기체에만 `next_flight_v1` capability를 알린다. 조종사는 하차, 충전 해제, 문 닫기를 끝내고 목표 SOC 이상일 때 `ground` 메시지의 `action: "next_flight"`로 같은 기체의 다음 예정편을 이어갈 수 있다. 이 요청은 현재 native pose와 배터리를 유지하고 계획, 자동비행 경로, 지상 절차만 다음 편으로 교체한다. 출발 허가는 자동으로 발급하지 않으며 새 비행편에서도 기존 PSU 출발 요청 절차를 그대로 거친다.

다음 예정편이 없거나 출발지가 현재 버티포트와 다르면 임의 비행을 생성하거나 기체를 순간 이동시키지 않고 이유를 표시한다. 시나리오 runtime이 현재 배정의 유일한 소유자이고, 브라우저와 `ManualGround`는 advisory 사본만 표시한다.

## 호환성
기존 클라이언트는 새 capability와 advisory 필드를 무시할 수 있다. 기존 `ground_handling_v1`, `ground_handling_v2` 동작과 기존 지상 action은 바꾸지 않는다. 다음 비행 action은 capability를 확인한 새 클라이언트만 전송한다.

## 검증과 한계
두 편이 편성된 같은 기체의 첫 운항을 GATE 보고까지 완료한 뒤 다음 편 정보, 충전 목표, 같은 기체의 재배정, 새 PSU 절차 초기화를 회귀시험한다. native 세션의 위치와 배터리가 계획 전환 시 유지되는지 확인한다. 실제 Unreal 화면에서 장시간 충전과 두 번째 이륙까지 이어지는 검증은 서버 재시작 후 별도로 수행해야 한다.
