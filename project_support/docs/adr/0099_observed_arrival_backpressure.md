# ADR 0099: 관측된 도착 적체를 출발 허가에 반영

## 배경

2026-09-16 실행의 07:19 관측에서 체공으로 표시된 48대 중 28대는 착륙 후 지상 출구를 기다렸고 5대는 주기장을 기다렸다. 초기 기체 132대와 전체 주기장 132개가 같아, 목적지 편중과 지상 회전 지연을 흡수할 여유도 없었다. 별도로 공중 경로 차단을 꺼도 대기 도착편 우선 검사가 출발을 막는 경로, 체공 중인 기체를 출발 진입 예측에서 제외하는 경로, 복귀하지 못하는 미접근 선행편이 후속편의 슬롯을 막는 경로를 재현했다.

## 결정

- 도착편 우선의 정적 공중 경로 비교에도 terminal_separation과 서로 다른 FATO 분리 가정을 동일하게 적용한다. 실제 패드, 인접 패드, 지상 점유 검사는 유지한다.
- 후보 출발의 도착 수요는 진입점 시각이 아니라 접근 시간을 포함한 예상 접지 시각으로 비교한다. 유효 간격은 설정 진입 간격, 접근 시작 간격의 두 배, 착륙 처리 간격 중 큰 값이다.
- 이미 지상 출발을 시작했거나 비행 중인 기체는 현재 위치의 남은 시간과 PSU 슬롯으로 예측을 갱신한다. 오래된 진입 예약이 만료되거나 체공점에 들어가도 사라진 수요로 취급하지 않는다. 겹친 ETA는 한 슬롯으로 합치지 않고 순차 처리 시간을 반영한다.
- 지상 지연 후 출발 시 실제 교통을 다시 확인한다. 기존 예약의 순서는 유지하고 뒤의 미출발 예약이 앞 예약을 계속 뒤로 보내지 못하게 한다. 회항 준비 시각과 진입 허가 시각을 구분한다. 도착 완료 시 진입 예약을 제거한다.
- 미접근 기체의 대기점 복귀 경로가 막혔으면 해당 편을 그 틱의 실행 가능한 선행편으로 보지 않는다. 번호와 기체를 삭제하지 않으며 이미 시작한 접근의 보호와 최종 점유 확인은 유지한다.
- PsuSequencer.refresh_arrivals의 내부 observation에 선택적 approach_wait_reason을 받아 지상 출구 문제와 복귀 경로 문제를 구분한다. 외부 API, wire schema, 기체 상태 소유권, 물리 적분 순서는 바꾸지 않는다. 예측을 위해 tick 안에서 native 사전 비행을 추가 실행하지 않는다.

## 범위와 한계

출발을 지상에서 늦추는 기능이지 처리 용량을 늘리는 기능이 아니다. 포화된 목적지, 실제 지상 장애물, 비행 중 실패, 장시간 회항 준비와 편중 수요는 대기를 계속 만들 수 있다. 기체를 이동시키거나 패드 점유를 지워서 적체를 해소하지 않는다. 기존 실행은 정책과 엔진을 유지하며 기록 보존 후 서버 재시작 및 계획 재적용으로 변경을 반영한다. 현재 운영 실행을 자동 초기화하지 않는다.

검증은 수정 전 실패 회귀시험, 지상 통행권을 사용하는 4대 FastPhysics/SimpleFlight 도착 시험 및 인접 회귀시험이다. 6,739편 전체 장시간 실행과 Unreal 검증은 완료 증거에 포함되지 않는다.
