# ADR 0028: 로컬 GUI 진입점의 안전한 기본 재시작

- 날짜: 2026-09-10
- 상태: 채택

사용자가 매번 `main.py`를 실행할 때 남아 있는 AeroDT 서버를 종료하고 새로
시작하도록 요청했다. 루트 진입점은 기본적으로 런처에 `--restart`를 전달한다.
`--reuse`는 이전의 서버 재사용을 선택한다. 모듈 직접 실행 기본은 유지한다.

종료 대상은 요청 주소/포트의 TCP listener 중 Python 실행 파일, 정확한
`-m user_application.apps.web_dashboard.launcher` 명령, 현재 저장소와 같은
working directory가 모두 확인된 프로세스다. 모든 listener를 먼저 확인한다.
권한 오류, 다른 폴더, 다른 명령이면 어느 프로세스도 종료하지 않는다.
종료 직전에 소유권을 재검증하고 PID 재사용을 검사하는 psutil Process를 쓴다.
프로세스 트리, 브라우저, 무관한 Python 프로세스는 일괄 종료하지 않는다.

Windows 새 런처는 Local 네임스페이스의 named event를 만들고 별도 감시
스레드에서 Uvicorn `should_exit`를 요청한다. 이벤트 이름은 저장소, PID,
프로세스 생성 시각의 해시이므로 이전 PID의 이벤트를 재사용하지 않는다.
외부에서 호출 가능한 HTTP 종료 API는 만들지 않는다. 최대 10초 정상 종료를
기다린 뒤 응답이 없거나 구 버전이면 확인된 서버만 강제 종료한다.
강제 종료 시 진행 중인 계산/저장은 중단될 수 있으며 콘솔에 명시한다.

검증: 임시 폴더의 실제 TCP listener를 사용하여 정상 종료와 구버전 강제
종료를 시험했다. 다른 checkout 식별, 혼합 listener, PID 재검증, 루트 옵션을
검증하고 기존 런처 시험을 함께 실행했다. 현재 사용자 서버는 소유권만 확인했고
이 작업에서 실제 운영 포트는 종료하지 않았다.
