# ADR 0068: Physical 운항 관측·분석 동기화

- 상태: 채택 / 2026-09-11

## 문제

Physical은 공통 ScenarioEngine, 지상 통제, PSU, native 조종사를 실행했지만 Twin에는 센서 패킷만 전달했다. 운항 분석·PSU·조종사·버티포트 화면은 수신 기체와 달리 Twin의 로컬 ScenarioSession을 조회했다.

## 결정

1. 기존 ScenarioSession의 읽기 전용 조회를 ScenarioObservation으로 추출한다. Physical은 native step 완료 후 같은 조회로 불변 운항 관측을 만든다. 엔진 상태·제어기를 복제하지 않는다.
2. GET `/api/v1/operations?run_id=&after=`는 버전 1 운항 관측을 제공한다. 실행 ID/프로세스/시작시각/관측 sequence, 현재 운영 보고, 분석 메타데이터, 최대 1,000건의 연속 이벤트 페이지를 포함한다. 실행이 바뀌면 계획·환경·정책·프로파일·규칙 해시를 함께 보낸다. 관측 시점 뒤의 이벤트는 다음 관측까지 공개하지 않는다.
3. 센서 네 그룹과 독립된 1초 주기의 HTTP 수집을 사용한다. 초기 이력은 빠르게 따라잡으며 완료 전에는 불완전한 분석을 공개하지 않는다. 입력은 16 MiB 응답, 128기체, 100시설, 20,000편 계획 한도로 검증한다. 소스 주소/세대 변경과 오래된 프로세스 응답을 구분한다.
4. 과거 보고와 이벤트는 Data에 등록한다. 송신·수신 양쪽 `data/workspace/physical_uam/operations/<run-id>/operations.json`에 기존 분석 형식으로 저장한다. 연결 종료·실행 교체에서 체크포인트를 보존한다. 정상 저장 주기는 5초이며 강제 프로세스 종료 때 마지막 구간을 잃을 수 있다. 기존 분석 기록의 32 MiB 읽기 한도는 유지한다.
5. `/api/operations/context/*`는 표시 중인 운항의 읽기 전용 조회다. Physical의 버티포트 환경·실제 점유·PSU 허가/슬롯/대기·조종사 지시/유도·승객 흐름을 보고한다. 수신 환경은 지도에 표시하되 저장된 Simulation 환경을 덮어쓰지 않는다. 정책/프로파일은 송신 측 실제 값을 읽기 전용으로 표시한다. 기본값과 생략된 기본값은 정규화해서 비교한다.
6. 기존 `/api/simulation/analysis` 경로는 호환을 유지한다. `recording=current`는 화면에 맞춰 선택하고 `physical`, `simulation`, `physical:<run-id>`로 명시적으로 조회한다. 분석 계산·CSV·비행편 상세는 같은 OperationsReports를 사용한다. UAM 수신 스위치가 켜져 있으면 운영 기록 수집은 지속하고, 로컬 Simulation 표시 여부는 기본 분석 선택에만 영향을 준다.
7. 센서 추정/불확실성 데이터와 운항 보고는 구별한다. 운영 보고로 센서 위치를 덮어쓰지 않는다. 수신 지연과 규칙/정책/프로파일 불일치를 공개한다. 중간 시각에서 시작하기 위한 선행 계산은 `reconstructed_through_s` 및 분석 기준 설명으로 구별한다. 새로운 분석이 과거 실제 수신을 소급 주장하지 않는다.
8. 점진적 업데이트 중 기존 서버에서 context API가 404이면 프런트엔드의 기존 Simulation 조회로만 호환한다. 500/통신 실패를 다른 운항 소스로 숨기지 않는다.

## 검증과 범위

관련 원격 Python 100/100, 로컬 Node 132/132, architecture PASS. 100대/18시설/1,825편 실제 Physical 스트림과 검증용 Twin에서 동일 관측 시점의 분석 totals가 정확히 일치했다. 운영 이력 페이지·재연결·보관·CSV·실제 지시·읽기 전용 설정 및 Chrome 분석/PSU/조종사 화면을 확인했다. native DLL과 실행 규칙은 동일하다. 전체 하루 운항·충돌·처리량·Unreal 임무를 이번 관측 연결 변경으로 다시 검증한 것은 아니다.

기존 원격 8766 서버는 별도 Simulation이 실행 중이므로 임의로 재시작하지 않았다. 소스는 반영했고, 별도 8767 검증 화면은 실제 Physical 입력을 사용한다. 기존 서버 적용은 진행 기록을 저장하고 재시작할 수 있는 시점에 완료한다. 상세 근거: `data/development_log/evidence/2026_09_11_physical_operations.json`.
