# ADR 0102: 정지한 접근 복귀 기체의 공통 진입점 우선순위

## 관측

2026-09-16 운영 계획 `914b2620bc5ed193-eb8c31`의 마곡(VP015)을 GET로 조사했다. 이 계획은 132대, 6,753편이며 이전 FATO 재배정 이벤트도 이미 존재한다. 수정 미적용이나 버티포트 수만으로 설명할 수 있는 상황이 아니었다.

06:55:54 관측에서 UAM0003과 UAM0048은 모두 약 496 m 고도에서 정지 복귀 상태였다. 두 기체는 하야동 2의 같은 진입점으로 향한다. `return_hold`가 존재하지만 이동 예약의 `movement_target`에는 실제 감속 목표가 아니라 진입점까지의 전체 미래 경로가 들어 있었다. 각 기체는 상대의 비행하지 않는 경로에 막혔다. 이 예약은 뒤의 도착편들도 막는다. 실제 교통이나 지상 자원 변화로 한 기체가 대기점으로 철수하면 풀릴 수 있지만, 동일 조건을 유지하면 상호 대기가 계속된다.

## 결정

1. 감속 명령의 `movement_target`은 실제 조종사에게 보내는 고정 정지 목표를 나타낸다. `return_hold`도 계속 유지하며 매 틱 현재 위치로 옮기지 않는다. 패드, 게이트, 접근 허가는 이 변경으로 해제하지 않는다.
2. 멈춘 모든 기체의 미래 경로를 무조건 풀지 않는다. 다른 기체를 계속 끼워 넣는 첫 후보는 12대 시험에서 대기를 증가시켜 폐기했다.
3. 같은 진입점을 공유하는 `returning` 기체 사이에서만, 관측상 진입점에 더 가까운 기체가 먼저 복귀한다. 거리 동률은 예약 시각과 편 ID로 결정한다. 검사용 우회 지점이 아닌 실제 관측 위치로 비교한다. 반복 순서가 바뀌어도 동일하게 판단한다.
4. 양보하는 기체가 수평 1 m/s 미만, 수직 0.3 m/s 미만이며 고정 정지 목표의 수평 8 m, 수직 3 m 이내일 때만 미래 합류 구간을 양보한다. 감속 중이거나 아직 목표에 도달하지 않았으면 기존 미래 경로 보호를 유지한다. 새로 진입하려는 미복귀 기체는 이 양보를 이용하지 못한다.
5. 미래 구간을 양보하더라도 관측 위치부터 정지 목표까지의 구간과 관측 속도의 lookahead 구간을 모두 보호한다. 실제 기체, 예약 대기점, 지형, 지상 출구, 패드와 terminal 검사는 그대로다. 수평 120 m, 수직 45 m, 예측 35초 등의 기존 설정을 낮추지 않는다.
6. 복귀 재개 시 `return_hold`를 지우고 실제 이동 구간을 다시 예약한다. 미리보기 성공은 실행 허가가 아니며 각 기체의 명령을 만들 때 다시 검사한다. 물리 상태나 native WP 인덱스를 Python에서 변경하지 않는다.

## 계약

ADR 0100의 "정지 중 전체 복귀 경로 유지"를 위 우선순위 조건으로 제한한다. `holding_assignment`의 기존 진단 필드만 사용하며 새 요청, wire 필드 또는 정책 옵션을 추가하지 않는다. 정지 중 `movement_target`의 의미를 실제 명령 목표와 일치시킨다. 오래된 기록의 `movement_target`이 진입점이어도 `return_hold`로 정지 명령을 구분할 수 있다.

## 검증과 제한

- 마곡의 실제 관측 좌표와 교통 표본으로 상호 차단을 재현한다. 수정 후에는 UAM0048의 같은 고도 복귀 구간만 가능해지고 실제 교통에 막힌 다른 경로는 계속 거부된다.
- 두 개의 독립 FastPhysics/SimpleFlight runtime을 같은 관측 형상에 배치한 별도 시험: 이전 판단은 600초 동안 둘 다 복귀 못함. 수정 후 가까운 기체는 61.5초, 다음 기체는 172.75초에 복귀점 통과 조건 충족. 이 시험은 live runtime을 복원한 것이 아니며 별도 수직 이륙으로 초기화했다. 250 ms 표본에서는 보호 간격 침범 없음. 순서를 뒤집은 회귀도 확인한다.
- 별도 12대/4-FATO 시험: 최종 수정 전후 모두 12편 완료, 모든 FATO 사용, 2,563초, 체공 누계 3,422 기체초. 전체 처리량이 개선됐다는 수치로 해석하지 않는다. 같은 시험에서 최소 공중 분류 기체 간 거리 2.717 m가 양쪽에 존재하므로 전체 교통의 충돌 안전을 보증하지 않는다.
- 조사와 수정 검증 중에는 운영 실행을 변경하지 않았다. 이후 사용자의 명시적 승인으로 07:06:09(50편 완료)에 stop 및 기록 저장 후 같은 폴더의 서버만 정상 종료했다. 기존 기록과 별도 백업의 7개 파일 해시가 일치한다. 동일한 6,753편 CSV의 schedule ID/해시를 확인하고 새 실행 `914b2620bc5ed193-b98ddc`에 재적용해 06:30부터 원래 2배속으로 재생했다. 재시작 후 상태에서 problems/pilot_failures 0을 확인했다. 전체 운영 계획, 실제 마곡 수정 후 혼잡 화면, Unreal, 연속시간 충돌 검증은 별도 확인이 필요하다.
