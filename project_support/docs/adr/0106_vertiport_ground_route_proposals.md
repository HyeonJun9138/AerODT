# ADR 0106: 버티포트 지상경로 제안과 PSU 선택

날짜: 2026-09-21

상태: 구현

## 배경

정기편 출발 준비에서 스탠드와 FATO 사이의 지상경로를 `ScenarioEngine`이 하나의
최단 경로로 만들었다. 지상관제는 이미 정해진 경로의 안전한 이동 구간만 허가했기
때문에, 짧은 경로가 점유된 경우에도 서로 겹치지 않는 다른 유도로를 출발 판단에
제안할 수 없었다. 이는 시설 내부 경로를 버티포트가 관리하고 PSU가 전체 출발 순서를
정한다는 역할 구분과도 맞지 않았다.

## 결정

`VertiportGroundControl`이 시설의 정적 유도로 그래프를 구성하고 스탠드에서 선택된
FATO까지 최대 두 개의 단순 경로를 비용 순으로 계산한다. 첫 번째는 최단 경로이며,
두 번째는 실제로 다른 노드열을 갖는 다음 최단 경로다. 없는 대체 경로를 임의의
직선이나 반대 방향으로 만들지 않는다.

각 `GroundRouteProposal`은 버티포트 ID, 안정된 경로 ID, 시작·종료 자원, 노드열,
로컬 north/east 좌표, 거리, 순위, 현재 진행 가능 거리와 방해 기체를 가진다. 이는
이동 허가가 아니다. 실제 지상 이동은 기존 `MovementAuthority`가 계속 통제한다.

`ScenarioEngine`은 Runtime의 실제 위치 관측을 버티포트에 전달하고 반환된 로컬
경로를 실행 좌표로 투영한다. 유도로 그래프를 탐색하거나 대안을 선택하지 않는다.
`PsuSequencer`는 버티포트 제안과 FATO, 도착 혼잡, 터미널 중첩 및 출발 간격을 함께
비교한다. 점유되지 않은 대안이 있으면 점유된 최단 경로보다 우선하고, 모두 같은
상태이면 기존 도착·슬롯 비용과 거리 순서를 적용한다.

현재 연결은 동일 프로세스의 typed call이다. 외부 전송은 추가하지 않으며 원격
버티포트가 연결될 때 별도의 communication adapter로 감싼다.

## 기록

운항 관리자가 보는 `events.jsonl`에는 버티포트가 제안한 경로의 거리, 순위,
진행 가능 거리와 방해 기체 및 PSU 최종 선택을 남긴다. 전체 노드열, 후보별 상세와
구성 탈락 사유는 같은 실행 폴더의 `diagnostics.jsonl`에 기록한다. 개발 진단 파일은
운항 상태, 허가 또는 분석의 권위 있는 입력이 아니다.

## 결과와 제한

시설 내부 경로 계산과 실제 이동 허가는 버티포트 책임으로 모이고, PSU는 시설별
제안을 받아 광역 순서를 결정한다. Simulation은 실행과 관측 전달에 한정된다.

현재 대안 수는 최단 경로를 포함해 두 개이며 출발 지상경로에 적용한다. 도착 후
주기장 재배정 경로는 기존 안전 트랜잭션을 유지한다. 대안도 점유된 경우 장래 해제
시간을 예측해 최적화하지 않고 기존 지상권한이 실제 관측에 따라 정지·재개시킨다.
