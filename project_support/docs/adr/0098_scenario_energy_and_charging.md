# ADR 0098: 다중 비행계획의 배터리 적산과 주기장 충전

## 범위와 소유권

다중 비행계획 ScenarioEngine의 기존 Aircraft가 배터리 상태를 소유한다. 기존 battery_pct는 같은 상태의 속성으로 읽고 쓰며 별도 복제 상태는 두지 않는다. FastPhysics/SimpleFlight 적분, 추력 및 조종 목표는 변경하지 않는다. energy.json은 airtaxi 모델 패키지의 버전 가능한 대표 제원이며 manifest의 energy-model이 가리킨다. 좌석별 용량과 기존 비행계획의 기준 전력은 이 파일에서 읽는다.

단일 비행계획의 기존 사전 계산/재생 전력 모델 및 외부 Physical UAM의 실측 센서값을 이번 변경으로 대체하지 않는다. 충전 케이블도 현재 다중 비행계획의 scenario 기체에만 적용한다.

## 소비 모델

시나리오 시간 dt에 소비 전력을 곱하여 kWh를 적산한다. 기본 4석 용량 110 kWh, 이륙/체공 320 kW, 순항 기준 130 kW이며 좌석별 대표 용량 비율로 스케일한다. 탑승 하중, 실제 관측된 속도와 tilt를 반영하며 느린 회전익 체공을 순항 전력으로 계산하지 않는다. 기준 상승률을 넘는 상승에 대해서만 추가 전력을 적용한다. 정지한 지상 이동 대기는 보조전력만 쓴다. 전원을 끈 주기는 소모 0으로 가정한다.

이 수치는 제조사 보증값이 아니다. 시각 자산의 이름과 실제 배터리/성능 제원은 일치한다고 주장하지 않는다. 모터별 실측 전력, 셀 전압과 온도, 열화, 전선/내부저항 및 풍속에 따른 공기속도는 아직 모델링하지 않는다. demand_kw는 성능 인증이나 항속거리 판정에 사용하지 않는다.

## 부족 시 연구 정책

잔량 20%, 10%, 0% 경계는 편당 각각 한 번 기록한다. SOC는 0 아래로 내려가지 않는다. 0 이후 요구되는 에너지는 deficit_kwh로 별도 누적하므로 요구 전력을 공급한 것으로 오인하지 않게 한다. 부족은 추락, 추력 감소, 자동착륙, 출발 금지, 파일럿 오류를 유발하지 않는다. UI는 '기록만/가상 비행 유지' 정책과 추정값임을 표시한다.

## 충전과 연결

FATO 착륙만으로 충전하지 않는다. gate_in이 끝나 주기장에 배치되고, 같은 기체의 주기장 점유가 확인되며, 속도/위치/높이가 맞아야 한다. 연결 대기 30초와 승객 하기 종료 중 늦은 시각 이후에 해당 stand의 충전기에 연결한다. 충전기가 없으면 unavailable을 기록하고 충전량을 만들어 내지 않는다.

기본 공급 전력 150 kW, 팩 제한 1.5 C, 충전 효율 92%, 보조 부하 1.5 kW, 목표 SOC 95%다. SOC 80% 이후 전력을 줄이며 충전 말기의 전력 비율은 10%다. 이는 SOC 영역의 CC/CV 유사 근사이지 전압 제어 BMS 시뮬레이터가 아니다. 충전 곡선은 구간별 해석 적분으로 dt와 배속에 따른 오차를 피하고, grid_kwh와 실제 저장 에너지를 구분한다. 충전 완료 후 연결은 출발까지 유지하며 추가 에너지 적산은 하지 않는다. 다음 출발은 기존 일정/관제 기준을 유지하고 충전을 끊는다. 목표 잔량을 못 채워도 출발을 강제로 막지 않는다. 잔량은 다음 편으로 이어진다.

하루 마지막 편이 종료된 뒤에도 시작된 충전이 끝날 때까지 정상 tick은 유지한다. 사용자의 중지/닫기는 충전을 기다리지 않고 현재까지의 기록을 저장한다. 명시적 reset은 배터리도 초기화한다.

## 기록과 wire 확장

- 기존 schema_version 1의 선택적 필드 추가: 상태 응답 energy/battery_pct/charging_connection, TwinEntity.charging_connection.
- immutable ChargingConnection은 충전기 소켓의 경위도/고도와 대표 기체의 포트 오프셋, 연결 상태를 담는다.
- 운항 사건 battery_flight_start/end, battery_sample, battery_low/critical/depleted, charging_connected/disconnected/complete/unavailable을 추가한다. 상세 표본은 단계 전환과 60초 간격, 임계 사건만 기록한다. 충전 완료 후 정지한 기체는 주기 표본을 중단한다.
- tracks.jsonl에는 SOC와 전력만 추가한다. operations.json에는 사용 모델 파라미터와 최종 에너지 상태도 남긴다. 분석과 CSV는 사용량, 0% 이후 부족량, 충전 입력, 최소 SOC를 제공한다. 과거 기록에 없는 값은 0이 아닌 미제공으로 유지한다.

## 시각화

기존 지도 WebGL 컨텍스트 안의 `Primitive` 하나(고무 튜브 메시 + 동체에 닿는 플러그 상자, 플랫폼과 같은 불투명 `PerInstanceColorAppearance`)로 그리고 별도 위젯을 만들지 않는다(2026-09-17: 처음의 Polyline/Point 컬렉션 선을 대체). 연결된 주기 기체에만, 버티포트 층이 알려 주는 캐비닛 몸통의 케이블 트랙(중간 높이)에서 스탠드 쪽 벽을 나와 데크를 따라 기체 측면 포트까지 케이블과 플러그를 표시한다. 지면/데크 보정은 비행체 표시 높이에 맞추며 시뮬레이션 좌표는 바꾸지 않는다. 모델 LOD에서만 표시하고 250 ms 간격으로 보정, 변하지 않은 geometry는 재생성하지 않는다. 연결 해제, 레이어 숨김, 시나리오 닫기, entity 제거 시 함께 제거한다. 기체 측면 포트 위치는 대표 오프셋이며 제조사 CAD 소켓에 대한 실측 정합은 미검증이다.

## 근거와 검증 범위

충전 특성 참고: [TI의 CC/CV 설명](https://www.ti.com/document-viewer/lit/html/SSZTA38/GUID-C54412B5-F5CE-4A85-A58C-61F29F501C0C).

위 자료가 본 대표 기체의 수치를 검증해 주는 것은 아니다.

검증은 에너지 보존, 충전 감속/스텝 독립성, 연속 편 SOC 유지, 실제 stand 점유, 기록 round-trip, 0% native 비행의 도착, 케이블 좌표와 자원 정리를 포함한다. 실제 운영 서버와 Unreal의 종단 검증 및 제조사 전력곡선 보정은 별도로 필요하다.
