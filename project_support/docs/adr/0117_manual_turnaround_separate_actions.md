# 0117 수동 TURNAROUND 문·승객·충전 조작 분리

## 문제

기존 `disembark`는 문 열기와 승객 하차를 한 번에 시작했고 `release`는 충전기
분리, 문 닫기와 절차 종료를 한 번에 처리했다. 사용자가 충전 전에 문만 닫으면
`released`가 되어 문, 하차, 충전을 다시 선택할 수 없었다. 조종사가 직접 내리는
기능도 승객 하차와 같은 버튼처럼 보였다.

## 결정

- `ground_handling_v3` capability를 추가한다. 기존 v1/v2와 wire envelope은 유지한다.
- TURNAROUND의 기체 절차는 `open_door`/`close_door`, `disembark`, `charge` 세
  버튼으로 나눈다. 각 요청은 독립적이며 앞 단계의 실제 상태가 충족돼야 한다.
- 문을 연 뒤 phase는 `door_open`이다. 이때까지 승객 수와 보행은 시작되지 않는다.
  `disembark`를 눌러야 보행 시계가 시작된다. `charge`는 하차 완료 뒤의
  `awaiting_charge`에서만 가능하다.
- 하차 전에 문을 닫을 수 있지만 `turnaround_complete=false`이므로 다음 비행은
  시작할 수 없다. `reopen`은 같은 operation을 복원해 승객을 중복 생성하지 않는다.
- `내려서 걷기`는 조종사 행동인 `crew_out`이며 세 기체 절차와 별도 행에 둔다.
  충전 중 또는 충전 시설이 없는 하차 완료 상태라는 기존 안전 조건을 유지한다.
- 구 클라이언트의 결합 `disembark`와 `release` 요청은 서버 호환 경로로 유지한다.
  새 클라이언트는 v3가 없는 구 서버에서 분리 조작을 비활성화하고 재시작 안내를 한다.

### 2026-09-22 후속 결정: 문과 절차 종료의 완전 분리

- `close_door`는 출입문만 닫는다. 충전 케이블을 분리하거나 operation을
  `released`로 바꾸지 않으며, 충전 중 닫아도 충전은 계속된다.
- 진행 중인 operation에는 독립적인 `door_state`와 `door_open`을 둔다. 문 버튼은
  `opening`, `alighting`, `awaiting_charge`, `connecting`, `charging`을 포함한 모든
  지상 작업 단계에서 사용할 수 있다. 문을 다시 열어도 승객 보행이나 충전 요청을
  새로 만들지 않는다.
- 문을 닫은 뒤에도 하차가 끝났다면 `charge`를 요청할 수 있다. 승객 하차 요청만
  실제로 문이 열린 상태를 요구한다.
- 다음 비행 가능 조건은 더 이상 `phase == released`가 아니다. 승객 하차 완료와
  실제 문 닫힘을 조합한 `turnaround_complete`를 사용한다. 구 클라이언트의
  `release`만 호환을 위해 기존 케이블 분리와 절차 종료 의미를 유지한다.
- 조종사 보행 기능은 사용자 요청으로 화면에서 보류했으므로 TURNAROUND에
  `crew_out` 버튼을 표시하지 않는다.

## 검증과 적용

문 열기만으로 승객이 움직이지 않음, 문 열기→승객 하차→충전 요청의 독립 순서,
하차 전 문 닫기/재열기, 충전 중 문 닫기와 케이블 유지, 승객 비중복, 다음 비행 완료 조건을
서버와 브라우저 시험으로 확인한다. Python 서버 재시작과 브라우저 새로고침 뒤
새 수동 세션부터 적용한다.
