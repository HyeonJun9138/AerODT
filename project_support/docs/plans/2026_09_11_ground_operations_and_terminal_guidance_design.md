# Verti-C 지상 통제와 이착륙 경로 유도 통합 설계

작성일: 2026-09-11

상태: 채팅에서 통합형 개선 방향 승인. 이 문서는 구현 전 검토본이며, 실행 코드와 운영 서버에는 아직 적용하지 않았다.

## 1. 목표와 적용 범위

출발 기체와 도착 기체가 같은 유도로를 각자의 시간표대로 통과하는 대신, 버티포트의 실제 점유 상태를 확인하고 허가받은 구간만 이동하도록 한다. 비행계획의 게이트는 우선 희망 배정으로 보존하며, 운항 중 배정은 실제 시설 상황에 맞춰 변경할 수 있게 한다.

공중에서는 단일 비행과 다중 비행이 사용하는 공통 RoutePilot을 보완한다. 이륙 연결선(C)과 접근 연결선(G)을 따라 속도와 높이를 함께 조절하고, 지나간 경유점을 다시 획득하려는 불필요한 왕복을 줄인다. 접근 수평속도 10 m/s는 유지해야 하는 목표가 아니라 설정된 상한으로 해석한다.

적용 대상은 웹 Simulation의 다중 운항과 Physical의 전체 운항이다. 두 실행 경로는 같은 ScenarioEngine과 조종사를 사용한다. 단일 비행에는 공통 경로 유도 개선을 적용하되, 존재하지 않는 다른 교통을 가정해 대기시키지 않는다.

## 2. 확인된 현재 동작

| 구간 | 확인한 내용 | 이번 설계의 대응 |
|---|---|---|
| 지상 이동 | ScenarioEngine은 gate_out/gate_in에서 경과시간을 증가시키고 Phase.at으로 위치를 계산한다. 유도로 통과 허가나 교차로 양보 판정이 없다. | 이동 가능 거리와 정지 위치를 통제하고 실제 진행량으로 지상 구간을 실행한다. |
| 교통 감시 | 현재 TrafficAwareness의 입력은 공중 기체이며 지상 기체는 제외된다. | 공중 감시와 별도로 버티포트 지상 통제를 연결한다. |
| 게이트 해제 | 출발 임무를 활성화할 때 leave_stand를 호출한다. | 임무 활성화, 실제 이동 시작, 게이트 이탈을 구분한다. |
| 지상 경로 | 계획에는 taxi_nodes가 있지만 ScenarioEngine의 Phase.detail에는 전달하지 않는다. | 원래 유도로 식별자와 실제 이동 곡선을 함께 보존한다. |
| 게이트 변경 | 빈 게이트 재배정 기능은 이미 있다. 예약과 실제 점유는 같은 장부에 섞여 있고, 배정이 없을 때의 재검토가 중심이다. | 실제 점유와 배정 예약을 분리하고 변경을 하나의 거래로 처리한다. |
| 변경 후 연결 | 현재 재배정은 FATO부터 시작하는 gate_in을 교체하며 승하차 메타데이터 복사와 이미 생성된 native 착륙 방위 갱신이 완전하지 않다. | 변경 시점에 따라 남은 이동 경로, 착륙 또는 지상 정렬 방위, 하기 동선을 함께 갱신한다. |
| 접근 유도 | 경로를 미리 보고 횡방향 속도를 보정하는 유도는 주로 고정익 구간에 적용된다. 접근은 현재 위치에서 목표점으로 향하는 방식이며, 중간 통과 판정에서 높이 오차를 별도로 관리하지 않는다. | C/G 경로 진행과 수직 도달 가능성을 함께 관리한다. |

독립 진단에서 출발 기체가 0 m 이동한 상태인데 게이트 점유가 해제됐고, 해당 계획의 실제 지상 이동은 약 22.485초 뒤 시작하도록 되어 있었다. 짧고 높은 90도 접근 시험에서는 다음 구간 시작 고도가 약 203.41 m로, 중간 목표 150 m보다 높았다. 그 시험의 최대 횡방향 오차는 약 44.66 m였으며 착륙은 완료했다.

이 진단에서는 사용자가 보고한 앞뒤 왕복 자체까지 재현하지 못했다. 따라서 이를 특정 원인으로 확정하거나 해결했다고 기록하지 않는다. 구현 검증에는 대기 해제, 급한 접근, 짧은 연속 구간, 실제 저장 항로를 추가한다. 당시 로컬 조회에서는 시나리오가 미로딩 상태여서 사진 속 UAM0021/UAM0070의 해당 순간 상태를 조회할 수 없었다.

## 3. 선택한 방식

**통합형 지상 통제와 공통 조종사 개선을 채택한다.** Verti-C가 시설 사용과 지상 이동 허가를 담당하고 PSU가 이착륙 흐름을 조정한다. 조종사는 이 허가와 경로를 따라 움직인다.

기체 사이 거리가 가까워지면 각각 정지시키는 방식만 추가하지 않는다. 이런 방식은 교차로 한가운데의 맞대기와 반복적인 정지·출발을 만들 수 있다. 반대로 전체 운항을 한 번에 다시 최적화하는 새 스케줄러도 만들지 않는다. 기존 일정, 항로, PSU 예약과 native 비행 엔진을 유지하고 부족한 실행 통제만 보강한다.

## 4. 책임과 계층 경계

| 구성 요소 | 책임 | 소유하지 않는 것 |
|---|---|---|
| VertiportGroundControl | 지상 이동 요청, 구간 사용권, 게이트 예약, 양보 순서, 변경 판단 | 기체 위치·속도의 별도 현재 상태 저장소 |
| PsuSequencer | 예상 도착, 패드 순서, 공중 접근 시작과 최종 착륙 허가 | 유도로 기체의 직접 이동 |
| RoutePilot | 허가된 C/G 경로 유도, 속도·고도·방위 목표, 천이와 최종 정렬 | 시설 점유 장부와 타 기체 물리 상태 |
| 기존 실행 경로 | 같은 시각의 관측 수집, 통제 입력 적용, 임무 진행 | 화면에서 계산한 위치를 이용한 실제 상태 보정 |
| Runtime | native 기체의 현재 물리 상태와 기존 이산 실행 순서 | 게이트 및 운항 순서 정책 |
| Data | 판단 변경, 실제 운항 시각, 배정 이력과 검증 근거 | 현재 기체 상태의 수정 |
| Visualization/Web | 현재 지시, 실제 배정, 대기 이유와 경로 표시 | 자체적인 이동 허가나 충돌 회피 |

새 능동 지상 통제는 `user_application/uam_mission`에 둔다. 정적 유도로 형상과 충돌 구역 계산은 `digital_twin/model_library`, 작은 불변 입력·출력 계약은 `digital_twin/contracts`를 사용한다. ScenarioSession과 PhysicalFleet이 통제 객체를 조립해 기존 엔진에 주입한다. simulation에서 user_application을 직접 import하지 않는다.

관측은 한 판단 주기 동안 읽는 입력이며, 통제 객체가 이전 위치를 모아 별도 현재 상태 버퍼를 만들지 않는다. 예약과 허가 이력은 물리 상태가 아니라 통제 상태다. 장기 과거 기록은 기존 Data 기록 경로로 넘긴다.

지상은 이번에도 기존 운동학 모사를 사용한다. 타이어, 견인차, 바퀴 마찰의 새 물리 모형을 추가하지 않으며 이를 native 접촉 물리로 표시하지 않는다. 기존 지상 위치 생성 책임을 관제 객체로 옮기거나 복제하지 않는다. 지상 실행기는 허가에 따라 진행량과 속도를 계산하고, 화면을 옮겨 겹침을 감추지 않는다. 기존 구조 전체의 이식과 동작 변경을 한 작업에서 섞지 않는다.

## 5. 공통 불변 조건

1. 하나의 실제 게이트에는 하나의 기체만 점유할 수 있다. 예약은 실제 점유를 덮어쓸 수 없다.
2. 서로 충돌하는 지상 구간의 동시 진입은 허가하지 않는다. 기체 중심점뿐 아니라 회전익을 포함한 지상 점유 형상을 사용한다.
3. 교차로를 빠져나갈 공간이 없으면 교차로에 진입시키지 않는다.
4. 일정 지연이나 대기시간 초과는 실제 점유 해제, 순간이동, 막힌 경로 강제 통과의 근거가 아니다.
5. 공중 순서는 기존 FATO와 C/F/G 항로 계약을 따른다. F는 양방향, C/G는 지정 방향을 유지한다.
6. 지상 통제로 생긴 지연은 해당 기체의 실제 운항시간과 후속 준비시간에 반영한다. 전역 시계를 멈추거나 예정 시각을 실제 시각으로 기록하지 않는다.
7. 일시정지 중에는 허가의 시간과 대기 누적도 멈춘다. 초기화 시에는 실행에 속한 예약과 요청을 함께 정리한다.
8. 실제 기체가 남아 있는 구간은 예약 기한 만료나 제어기 오류만으로 빈 구간이 되지 않는다.

## 6. 지상 이동 통제

### 6.1 유도로와 충돌 구역

기존 레이아웃의 노드·에지와 계획의 taxi_nodes를 유지한다. 둥글게 다듬은 실제 이동 경로를 함께 검사해, 노드를 공유하지 않더라도 경로가 교차하거나 기체 폭 때문에 겹치는 구역을 찾는다. 같은 유도로의 역방향 통행, 합류, 게이트 진출입, FATO 출구를 모두 포함한다.

점유 형상은 모델 자료의 지상 크기와 운용 여유를 사용한다. 카메라 거리, 화면 확대, 최소 표시 픽셀 크기는 통제 크기에 영향을 주지 않는다. 형상 자료가 없으면 명시적인 보수적 대체 크기를 사용하고 진단에 표시한다. 대체 크기를 0으로 두지 않는다. 레이아웃 버전과 형상 버전을 기준으로 정적 계산을 재사용한다.

정지 위치는 기체 전체가 충돌 구역 밖에 있고 다른 통행을 막지 않는 경로상의 지점이어야 한다. 사용할 수 있는 대기 지점이 없으면 이전 안전 지점이나 게이트에서 기다린다. 임의의 데크 빈 공간이나 유도로 밖으로 이동시키지 않는다.

### 6.2 이동 허가와 양보

모든 기체의 같은 시각 관측으로 요청을 모은 뒤 결정한다. 허가는 다음 안전 정지 지점까지의 이동 구간과 도달 가능한 최대 진행량을 포함한다. 교차 구역과 그 뒤 정지 공간을 함께 확보한다. 아직 진입하지 않은 향후 예약은 재조정할 수 있지만 실제 점유권은 관측 이탈 전까지 유지한다.

우선순위는 이미 진입해 빠져나가야 하는 기체, 착륙 후 패드 이탈, 누적 대기와 운항 시각을 고려한 요청 순서로 정한다. 같은 조건에서는 안정적인 식별자 순서로 결정해 실행마다 결과가 바뀌지 않게 한다. 지속적으로 도착편만 우선해 출발편이 밀리지 않도록 대기 증가분을 반영한다. 우선순위가 높아도 막힌 출구로 들어갈 권한은 생기지 않는다.

맞대기 고리는 허가 전에 검사한다. 아직 사용하지 않은 예약을 철회해 해결할 수 있을 때만 재배정한다. 물리적으로 비킬 곳이 없는 상태나 초기 배치 중첩은 `지상 경로 막힘`으로 보고하고 추가 진입을 차단한다. 해결할 수 없는 배치를 정상 운항으로 꾸미지 않는다.

### 6.3 실제 이동과 시간

기존 곡선 경로와 선회 속도 제한을 유지하되, 고정 경과시간 재생 대신 실제 진행 거리와 속도를 사용한다. 정지 지점까지의 거리, 현재 속도, 기존 지상 가감속 한계, 다음 판단까지의 이동 여유를 고려해 미리 제동한다. 대기 해제 후에도 즉시 원래 속도로 뛰지 않고 다시 가속한다.

탑승, 시동 및 준비 대기는 이동 진행량과 구분한다. 탑승이 끝나지 않은 기체는 허가가 있어도 출발하지 않는다. 반대로 유도로 대기 중에는 승객 탑승 연출을 처음부터 재생하지 않는다.

임무 활성화 시각은 이동 요청 시각으로 보관한다. 실제 off-block은 기체가 게이트에서 움직이기 시작한 관측으로 기록하고, 게이트 해제는 전체 점유 형상이 게이트 구역을 벗어난 때 기록한다. FATO 해제도 같은 원칙으로 판정한다. 이 시각 의미 변경은 ADR과 분석 회귀시험에 포함한다.

## 7. 게이트의 예약, 점유 및 변경

원래 비행계획은 수정하지 않는다. 계획 게이트, 현재 배정 게이트, 실제 주기 게이트를 구별한다. 게이트 점유 사실의 출처는 기체 관측이며, 예약은 별도의 배정 상태다. PSU와 Verti-C가 서로 다른 두 개의 권위 장부를 갖지 않도록 기존 StandTimeline 호출은 동일한 배정 경계로 연결한다.

도착 요청 시 계획 게이트를 우선 검사한다. 사용할 수 없다면 실제로 연결된 유도로, 점유 및 확정 예약, 이동 중 충돌 부담과 예상 대기를 비교해 대체 게이트를 선택한다. 기체나 충전시설의 적합성 자료가 있으면 그 조건도 검사한다. 자료가 없는 적합성을 확인된 것으로 표시하지 않는다.

빈 공간이 없으면 도착편을 접근 전에 조절한다. 출발 예정 시각이 지났다는 이유로 점유 게이트를 비었다고 추정하지 않는다. 동시에 FATO 출구와 다음 안전 정지 공간이 확보되는지 확인해, 게이트만 예약하고 출구가 막힌 패드에 새 기체를 내려보내지 않는다.

배정은 다음 세 시점으로 나눈다.

- **접근 전:** 상황에 맞춰 재배정할 수 있다. 같은 비용의 후보 사이에서 매번 바꾸지 않고 기존 배정을 유지한다.
- **최종 접근부터 착륙까지:** 유효한 배정은 유지한다. 배정이 불가능해지면 지상 출구를 다시 확인하고, 최종 진입 전에 기다린다. 이미 수직 착륙 중인 기체를 게이트 변경 때문에 옆으로 유도하지 않는다.
- **착륙 후 이동 중:** 막힌 경로 등 예외가 있을 때만 안전한 위치에 정지한 뒤 재배정한다. 현재 위치부터 이어지는 경로를 만들며 FATO나 이전 게이트 위치로 되돌려 시작하지 않는다.

변경 후보의 게이트 예약, 남은 유도로, 도착 방향, 하차 동선, 배정 이력을 먼저 모두 검증한다. 검증된 묶음만 한 번에 적용하고 이전의 미사용 예약을 해제한다. 실패하면 이전 유효 배정을 유지하거나 대기 상태로 남는다. 일부만 갱신된 상태는 외부에 공개하지 않는다.

native 착륙 방위는 최종 정렬에 들어가기 전의 변경만 조종사에 전달한다. 이미 최종 정렬 또는 수직 착륙에 들어갔다면 기존 방위를 유지하고 접지 후 지상에서 정지·정렬한다. 이 변경으로 native 위치, 적분기, 비행 경과를 초기화하지 않는다.

## 8. C/G 경로와 수직 비행 유도

### 8.1 경로를 따른 진행

C/G에서도 현재 구간에 대한 투영 위치와 속도에 맞는 앞보기 지점을 사용한다. 현재와 다음 순서 구간만 참조하며, 근처에서 교차하는 다른 항로로 건너뛰지 않는다. 곡선과 짧은 연속 구간에서는 미리 방위와 속도를 조절한다.

일반 경유점의 약 150 m 통과 반경은 기존의 선호 기준으로 유지하며 강제 fly-over 조건으로 만들지 않는다. 지나간 점의 위치를 다시 찍기 위한 진행 되감기는 하지 않는다. 단, 마지막 FATO 상공 정렬점과 수직 착륙은 일반 통과점처럼 생략하지 않는다.

대기 후 복귀는 허가된 현재 또는 다음 경로 구간으로 연결한다. 이전 목표점이나 대기 시작 고도로 무조건 돌아가지 않는다. 안전한 복귀 경로가 없으면 그 이유를 표시하고 대기를 유지한다.

### 8.2 경로별 속도와 하강 준비

남은 G 경로 길이와 목표 높이, 실제 수평·수직 속도, 가감속 능력, 틸트 전환 시간을 함께 계산한다. FATO 상공 정렬점부터 역으로 필요한 감속·하강 여유를 확인해, 접근에 들어오기 전에 역천이와 감속을 준비한다.

하강은 허용된 경로 높이와 지형 여유 안에서 수행한다. 짧은 G 경로 때문에 높이를 맞추기 어렵다고 F 순항 고도를 임의로 낮추거나 지형을 관통하지 않는다. 이런 경우에는 더 일찍 속도를 줄이고 G 구간에서 가능한 하강 시간을 확보한다. 끝까지 도달 가능한 접근을 만들 수 없다면 최종 진입 전에 명시적인 대기로 처리하며 목표점 주변을 앞뒤로 반복 이동시키지 않는다.

`approach_horizontal_speed_mps`는 접근 상한이다. 기존 사용자 설정이 4 m/s면 그대로 상한 4 m/s로 사용한다. 기본 10 m/s에서도 경로 경사, 선회, 높이 오차와 제동 여유에 따라 더 느리게 접근할 수 있다. 불필요하게 낮은 속도를 항상 강제하지 않는다.

중간 WP를 횡방향으로 통과하더라도 남은 고도 오차를 소실시키지 않는다. 다음 구간에 그 오차와 수직 제어 상태를 이어서 전달하고, 남은 거리로 수직 목표에 도달 가능한지 확인한다. 수평 진행과 무관하게 매 구간에서 높이 목표를 새로 잡아 급하게 보정하지 않는다.

### 8.3 기존 동작 보존

수직 이륙, 상공 정렬, 전진 및 천이의 순서를 유지한다. 방향 정렬 중에 목표 높이가 데크 고도로 바뀌지 않아야 한다. 고정익 선회 중의 고도 유지와 순항 우측 경로 추종은 회귀시험으로 보호한다.

허용된 소각도 로터 보조 틸트는 유지하되 실제 조종사 상태와 모형 한계를 따른다. 마지막 수직 착륙 전에는 실제 틸트와 속도, 방위가 안정된 것을 확인한다. 고도를 맞추기 위해 위치·속도·회전수를 직접 덮어쓰거나 공력 계수를 임의로 낮추지 않는다.

## 9. 계약, 화면과 기록

지상 판단의 입력에는 실행/시각 식별자, 기체와 임무 식별자, 현재 관측, 지상 진행 구간, 경로 버전, 준비 상태를 담는다. 출력은 다음 안전 정지 위치까지의 이동 권한, 속도 상한, 차단 기체와 구역, 배정 버전, 이유다. 이전 경로 버전의 허가는 새 경로에 적용할 수 없다. 허가의 유효성은 벽시계가 아닌 실행 시계로 판정한다.

기존 정보창과 Verti-C/PSU 패널을 확장하고 별도 반복 조회 창은 만들지 않는다. 다음 정보를 표시한다.

- `도착 기체 UAM0070 통과 대기`처럼 대상과 이유가 있는 지상 지시
- 이동 허용 지점, 현재 구역, 대기 누적과 마지막 판단 시각
- 계획 게이트와 현재 배정 게이트, 변경 사유
- `접근 고도 조정`, `역천이 안정화`, `착륙 출구 확보 대기`처럼 실제 판단에서 나온 접근 상태

지상 대기를 공중 체공으로 표시하지 않는다. 기존 기체 이름과 운항 상태의 독립 표시 설정은 유지한다. 속도가 느리다는 이유만으로 대기 사유를 추측하지 않는다.

판단 변경, 허가와 해제, 배정 변경은 기존 Data 실행 기록에 연결한다. 같은 지시를 매 tick 새 사건으로 쌓지 않되 실제 상태 전환과 서로 다른 기체의 판단은 생략하지 않는다. 원래 계획과 배정 이력은 함께 보존한다.

Physical의 운항 판단은 실행 중인 PhysicalFleet 쪽에서 수행한다. Twin은 전달받은 센서와 운항 정보를 읽을 뿐, 수신이 늦었다고 독자적인 지상 허가를 생성하지 않는다. 공유 구현을 쓰더라도 두 별도 실행의 예약을 섞지 않는다. 센서 결측이나 전송 지연을 게이트 이탈로 해석하지 않는다.

Python 계약과 웹 응답은 기존 소비자를 깨지 않는 추가 필드를 우선한다. native 착륙 방위 갱신에 필요한 C ABI는 버전/기능 확인을 추가하고, 지원하지 않는 라이브러리에서 변경을 조용히 무시하지 않는다. 실제 공개 계약 변경은 구현 시 ADR에 명세하고 구버전 거부·호환 시험을 추가한다.

## 10. 검증 기준

| 검증 묶음 | 필수 사례와 판단 기준 |
|---|---|
| 점유 | 기체가 아직 게이트에 있으면 예약 요청과 무관하게 점유 유지. 탑승 중, 정렬 중, 저속 이탈, 출발 실패에서도 동일. |
| 교차로 | 정면 대향, 직각 교차, 합류, 같은 구간 후행, 게이트 출구 교차. 실제 기체 점유 형상 및 스텝 사이 이동 형상에 중첩이 없어야 함. |
| 대기와 재개 | 제동 한계 안에서 안전 지점에 멈추고 상대가 이탈한 뒤 가속. 교차로 안 맞대기와 허가 반복 진동을 방지. 독립 구역은 동시에 이동 가능. |
| 막힌 배치 | 대기 공간 부재, 초기 중첩, 모든 게이트 점유, 경로 단절. 강제 통과나 위치 보정 없이 이유를 보고. |
| 게이트 변경 | 예약 경쟁, 물리 점유와 예약 구분, 실제로 비는 게이트, 최종 접근 중 배정 보호, 이동 중 안전한 재계획. 계획 원본 불변과 하기 위치 일치. |
| 접근 | 기존 직선과 짧고 높은 접근, 좌우/S자 G 경로, 연속 짧은 WP, 높이 기준이 다른 데크, 대기 후 복귀. 실제 높이·속도·틸트·구간 진행을 측정. |
| 왕복 | 정상 접근에서 지난 WP를 다시 획득하기 위한 유도 명령이 없어야 함. 실제 역방향 거리와 횟수도 별도로 기록하며 명령만 보고 통과로 판단하지 않음. |
| 기존 비행 | 시동, 수직 이륙, 정렬, 천이, 고정익 고도 유지, 우측 순항, 역천이, 수직 착륙 회귀 유지. |
| 시간과 상태 | pause/resume/reset, 1~10배 재생, 구간 중 취소, worker 실패. 한 시각 관측에서 기체 나열 순서를 바꿔도 같은 통제 결과. |
| UI/Physical | 실제 원인 표시, 지상 대기/체공 구분, 게이트 변경 이력, 오래된 판단의 지연 표시. 수신 측 제어 중복 없음. |

지상 기하 판정은 한 순간의 중심점 최소거리만으로 검증하지 않는다. native 접근은 현재의 0.02초 물리 스텝 결과를 활용해 과도한 역방향 이동과 수직 속도, 최종 착륙 위치를 확인한다. 일반 경유점의 150 m 선호 범위를 전체 경로의 절대 합격 조건으로 오해하지 않는다.

현재 저장 계획의 다기체 재현은 동일한 입력·정책·환경 사본으로 전후 비교한다. 먼저 100기체 혼잡 구간을 비교하고 이어 전체 일정을 시험한다. 완료 편수, 지연, 각 대기 원인, 무진행 고리, 최소 분리, 허가 위반과 처리 비용을 기록한다. 안전한 통제로 완료 편수가 줄 수 있으므로 처리량만으로 개선을 판단하지 않는다. 반대로 시설이 실제로 포화된 대기를 모두 결함으로 세지 않는다.

정적 충돌 구역은 재사용하고 동적 판단은 같은 버티포트와 관련 구역의 기체로 제한한다. 100기체에서 통제 계산 시간과 실효 실행 배율을 전후 측정한다. 전체 형상 검사를 매 프레임 다시 하거나 새로운 HTTP polling으로 성능을 보완하지 않는다.

관련 Python, native CTest, 웹 회귀와 architecture 검사를 실행한다. 실제 Unreal 임무 및 화면 증거를 전체 완료 조건에 포함한다. 실행 정책이나 환경 문제로 Unreal을 검증하지 못하면 그 한계를 명시하고 전체 완료로 기록하지 않는다.

## 11. 구현 단위와 적용

하나의 통합 설계 아래 다음 순서로 구현 계획을 세운다. 각 단위는 실패하는 회귀시험을 먼저 만들고, 해당 동작을 최소 범위로 수정한다.

1. 지상 경로 식별자와 관측/허가 계약, 실제 게이트 이탈 판정
2. 교차 구역 사용권과 제동·대기·재개, 동시 진입 및 맞대기 방지
3. 실제 배정과 게이트 변경 거래, PSU 최종 허가와 지상 출구 연결
4. 공통 C/G 유도와 경로별 하강·속도 조절, native 회귀
5. 정보창·판단 기록·Physical 연결과 다기체 종합 검증

주요 수정 경계는 `user_application/uam_mission`, `digital_twin/contracts`, `digital_twin/model_library/ground_motion.py` 및 지상 경로 형상, `digital_twin/simulation/scenario_engine.py`, `psu_sequencing.py`, `decision_policy.py`, 기존 웹 역할 패널, Physical 조립부다. 관련 없는 기체 형상, 학습 예측 모델, 센서 잡음, 지도 로딩, 배경 데이터 공급자는 변경하지 않는다.

실행 중인 운항에 새 정책이나 DLL을 부분 적용하지 않는다. 검증 결과와 재시작 범위를 먼저 설명하고, 사용자가 허용한 시점에 계획과 과거 기록을 보존한 뒤 적용한다. 현재 Physical 운항과 Twin 서버는 이 설계 작성 과정에서 중단하지 않는다. 기존 항적을 보존하는 것과 native 물리 상태를 완전히 복원하는 것은 다른 기능이므로 동일하다고 안내하지 않는다.

## 12. 이번 범위 밖

새 항공교통 법규 체계, 실제 항공기 관제 인증, 견인차/서비스 차량 모사, 실물 바퀴 접촉 물리, 전체 보행자 충돌 회피, 자동 대체공항 회항과 새 공역 생성은 포함하지 않는다. 승하차 완료와 기체 출발의 연결 및 게이트 변경 후 하기 동선 일치는 이번 범위에 포함한다.

이 설계는 시뮬레이터의 실행 일관성과 재현성을 높이기 위한 것이며 실제 운항 안전 인증을 의미하지 않는다.
