# 기체 카메라와 비행물체 탐지 설계

작성일: 2026-09-14
상태: 사용자가 승인한 화면 방향을 구체화한 구현 전 검토본

## 동작
항공기 또는 UAM을 명시적으로 선택하면 기체 카메라 창 하나를 연다. 같은 창을 중복 생성하지 않고 선택 기체를 바꾼다. 초기 상태는 전방 카메라와 AI OFF다. 위성은 대상에서 제외한다. 수동으로 닫은 창을 단순 텔레메트리 갱신이 다시 열지 않는다. 단일 기체 시뮬레이션 경로도 같은 선택 흐름으로 연결한다.

주변 교통 레이더의 기본 창 크기와 색상, 공통 창 배치를 사용한다. 방향 선택은 기체 실루엣 주위의 앞, 뒤, 좌, 우 버튼과 별도 하방 버튼으로 구성하고 선택 상태와 접근성 이름을 제공한다. 영상은 비율을 유지하며 작은 창에서도 조작부가 잘리지 않는다. AI Model ON/OFF 버튼과 작은 상태 표시 외 불필요한 설명은 두지 않는다. 영상은 웹 3D 장면으로부터 생성한 시뮬레이션 영상임을 표시한다.

## 카메라
기존 digital_twin/visualization/web/airframe_camera.js의 별도 저해상도 렌더러를 확장한다. 현재 주 지도 카메라와 동역학을 움직이지 않는다. 기존 코드의 rear 방향 계산은 있지만 set 허용 목록에서 빠진 부분을 회귀시험으로 보완한다. 기존 조종석 카메라 동작은 유지한다.

기체의 실제 표시 행렬과 모델 기준축을 사용한다. 자세가 없으면 마지막 자세 유지 상태를 알리고 유효한 시점이 없을 때 가짜 영상을 만들지 않는다. 576x288 기본 영상으로 시작하며 선택 방향 하나만 렌더링한다. 초기 6 FPS 수준에서 측정하고 부하에 따라 낮춘다. 20~30 FPS는 보장하지 않는다. 최소화, 닫기, 숨겨진 탭에서 렌더링과 프레임 전송을 중지한다.

## AI와 모델
AI OFF에서는 모델 로드와 추론 요청이 발생하지 않는다. ON일 때만 로컬 추론 경로를 시작한다. 영상은 외부 AI 서비스에 전송하지 않는다. 첫 ON에는 로딩 상태를 표시하고 실패해도 카메라는 계속 표시한다.

후보: Javvanny/yolov8m_flying_objects_detection. 모델 카드에 Bird, Drone, Airplane, Helicopter와 Background가 명시되어 있다. https://huggingface.co/Javvanny/yolov8m_flying_objects_detection

모델 카드의 MIT 표기만으로 의존성 전체를 MIT로 취급하지 않는다. 원본 가중치와 기반 YOLO의 사용 조건, 실제 파일 및 클래스 매핑을 확인하고 출처와 해시를 모델 manifest에 기록한다. 외부 체크포인트는 임의 pickle 코드를 실행하는 방식으로 로드하지 않는다. 검증 가능한 안전한 가중치 로드 또는 ONNX 경로가 확보되지 않으면 연결 실패를 명시한다.

UAM 전용 학습은 확인되지 않았다. Drone 탐지를 UAM으로 이름만 바꾸지 않는다. 실제 기체 영상에서 해당 모델의 일반화 성능을 평가하고 탐지하지 못한 객체에 임의 박스를 만들지 않는다. 배경 클래스는 표시하지 않는다.

YOLO 탐지 후 ByteTrack으로 추적 ID를 유지한다. 학습 모델의 출력과 시뮬레이터 정답 좌표를 분리하며 좌표 기반 박스를 AI 결과로 사용하지 않는다. 전방 영상에 대한 지상 관측 학습 모델의 성능 저하 가능성을 검증 결과에 기록한다.

## 처리와 경계
시각화는 영상 생성만, user_application은 UI와 실행 조립만, communication은 영상 및 결과 전송만 담당한다. 인식 계산은 동역학 밖의 독립 모듈로 두고 ADR에 새 책임 및 wire contract를 기록한다. 모델 가중치와 manifest는 digital_twin/model_library에 둔다. 추적 상태는 영상 세션의 파생 상태이며 runtime 현재 상태를 수정하지 않는다.

프레임에는 세션, 기체, 방향, 순번, 캡처 시각, 크기를 포함한다. 응답은 같은 식별자와 원본 영상 좌표의 박스, 클래스, 신뢰도, 추적 ID 및 처리 시간을 반환한다. 요청 크기와 해상도 상한을 검증하고 동시 추론은 하나로 제한한다. 처리 중 새 프레임은 쌓지 않는다. 세션별 추적 상태는 종료하거나 일정 시간 요청이 없으면 해제한다.

AI는 최대 5회/초로 시작하되 실제 지연에 맞춰 낮춘다. ON 화면은 처리한 영상과 해당 박스를 함께 표시하여 현재 영상 위에 오래된 박스를 붙이지 않는다. 늦은 결과는 폐기하고 1초 이상 지연하면 박스를 숨기고 지연 상태를 표시한다. 방향 및 기체 변경, AI OFF 이후 도착한 응답은 무시하며 추적을 초기화한다.

## 검증
- 초기 AI OFF와 무추론, 명시적 선택만 창 열기, 중복 창 방지, 단일 기체 선택.
- 다섯 방향 카메라 자세 및 기존 조종석 회귀.
- 기체/방향 변경 중 지연 응답 폐기, 추론 중복 방지, 해제와 최소화.
- 프레임 좌표와 박스 일치, 영상 비율 및 작은 창 레이아웃.
- 모델 실제 클래스와 출처 검증, 실제 이미지 추론 및 연속 프레임 추적 시험.
- 실제 브라우저에서 기본 카메라와 AI ON/OFF 확인, 처리 시간 및 지도 영향 측정.
- 새 또는 UAM이 없는 장면을 탐지 성공 증거로 제시하지 않는다. UAM 임무와 native Unreal 검증을 하지 않았다면 따로 명시한다.
