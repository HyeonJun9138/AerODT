# 사용자 창 배치 기능 구현 계획

승인한 설계: 기존 디자인과 중앙 지도 유지, 일반 정보창 공통 이동/크기 조절, 좌우의 작은 영역과 하단 3칸 스냅, 최소화 탭, 배치 저장 및 초기화. MFD와 기체 제어는 제외한다.

1. 화면 안으로 제한하는 배치와 스냅 계산을 순수 함수로 구현하고 경계 시험을 먼저 작성한다.
2. 일반 창 DOM을 감싸는 표현 전용 셸을 추가한다. 원래 창의 데이터와 생명주기를 유지하고 이동/크기/최소화만 담당한다.
3. 서로 무관한 창을 닫는 앱 조립 콜백을 제거한다. 단일 편집 패널 안의 탭 전환 및 비행 시나리오의 생명주기는 유지한다.
4. 원래 창 닫기, 데이터 갱신, 화면 축소, 키보드 조작, 저장 실패를 시험한다.
5. 실제 브라우저에서 여러 창 배치와 스냅, 크기 조절 및 MFD 아래/위 관계를 확인하고 개발 로그를 갱신한다. 서버 재시작은 하지 않는다.

## 2단계 승인 반영: 독립 다중 창 (2026-09-14)

사용자가 같은 메뉴를 누를 때마다 새 창을 열고 직접 닫는 방식을 승인했다. 1단계의 공유 drawer 유지 제한을 해제한다. 작업 폼은 별도 컨트롤러와 ShadowRoot로 분리하고 상세창은 생성 레시피로 새 인스턴스를 만든다. 설정과 실행 컨트롤은 동일 소유자의 별도 뷰로 두어 시뮬레이션을 복제하지 않는다. MFD는 조종석 소속을 유지한다.

최소화와 닫기, 제목줄 색상, 배치와 크기 조절을 통일한다. 창 종료와 시나리오 또는 재생 종료를 분리한다. 독립 폼, 반복 생성, 상태 전달, 개별 종료와 텍스트 갱신 중 버튼 보존을 회귀시험으로 검증했다. 최종 시험과 제한사항은 development_log의 multiwindow 증거에 기록한다.
